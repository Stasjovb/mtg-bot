## What this campaign is

We're driving cross-engine parity between two MTG engine implementations in the same repo:

- **Python engine** at `src/mtg_bot/` (the source of truth for rules behavior; ~13k statements)
- **Rust engine** at `rust/src/` (the production self-play backend; compiles to `mtg_bot_engine.pyd` via maturin)

The goal: both engines produce byte-equal state after every legal action, for every EoE card the bridge admits. We're not at 100% coverage — but we have the infrastructure and process to get there one cell of the coverage matrix at a time.

## The work pattern

Parallel sub-agents, each takes a slice, ships end-to-end (build, gate, rebase, merge, push), reports back. Typical rounds:

- **2-3 agents** for normal rounds (sometimes 4 if there's enough disjoint work)
- Each agent: 1 branch, 2-4 commits, auto-merge to `origin/main` with `--no-ff`
- **Push-immediately protocol** for parallel slices: merge + push one slice before starting the next; smaller time windows = fewer sentinel collisions (round 24 validation)
- Rust slices serialize through `maturin develop --release` rebuild; only ONE Rust agent per round to avoid `.pyd` race
- Python slices parallelize freely
