# cost-reduction Phase-1 — implement-ready spec (sub-shape A: the 2 spell-local boolean-condition cards)

## 0. Why this doc exists

`docs/COST_REDUCTION_SUBSTRATE_PLAN.md` (round-60 N2) established:
cost-reduction is roadmap **#2** by single-gate deck-count (5 cards /
53,648 decks, all single-gated, count HONEST — the parser does NOT
over-attribute), but the bridge-correct *realizable* yield is **0 in
any near-term clean slice**: `CardDef` has no cost-reduction field,
Rust's `CardPrinting` has none (the `cards.rs:4180` deferral comment),
Rust has no `apply_cost_reductions` analogue, and the reduction fires
on the cast pipeline the bench *always* drives (asymmetric drop, no
symmetric-bit-equality escape hatch — strictly worse than warp). It is
a genuine multi-round Rust cost-mechanic substrate **strictly larger
than warp** because it requires a `Condition`-grammar port, not just a
`ManaCost` field.

The agreed cost-mechanic sequence is **warp_cost (Phase 1 executing
now) → cost-reduction**. This doc is cost-reduction's Phase-1 spec: the
precise CardDef field, the Rust `CardPrinting` field + parse, the
minimal `Condition`-subset port, the cast-pipeline hook (the key DIFF
vs warp — see §3.4), the bidirectional bridge arms, the filter
guardrail, the pin plan, the genuine-real-EoE-probe plan, the
per-phase EoE-pool delta, the phase boundaries, and the §2 audit
confirming the path is bridge-correct once both engines compute the
reduced cost identically. A future Rust round (after warp Phase 1

**Why "spell-local boolean-condition" is the clean Phase-1 boundary:**
Gigastorm Titan / Lashwhip Predator cost-reduction is *only* "if a
boolean state predicate holds at cast time, this spell's generic mana
shrinks by a fixed `amount`". No variable multiplier (Phase 2), no
battlefield scan over other permanents (Phase 3), no target-dependent
rider, no external. It is the minimal cost-reduction shape and
exercises the entire Phase-1 substrate (new field + the two-condition
port + the cast-cost hook + the bridge round-trip) without rider
interaction. This is the round-59 sub-shape-split discipline:
front-load the smallest self-contained slice; each phase independently
shippable + gate-green.

## 2. Bridge-correctness audit (§2) — confirms Phase 1 is bridge-correct ONCE both engines compute the reduced cost identically

### 2.1 The pre-substrate state (the divergence Phase 1 closes)

Verified live:

- **Python models the full cost-reduction.** `apply_cost_reductions`
  (`actions.py:406`) is invoked **unconditionally on the cast
  pipeline** (`actions.py:1583`, inside `_cast_spell`, AFTER mode +
  target selection at `actions.py:1567,1576`, BEFORE kicker at
  `actions.py:1588`) and again on the `legal_actions` affordability
  probe (the `_can_cast` path). For each `rule in
  printing.cost_reductions` it calls `_evaluate_cost_reduction`
  (`actions.py:441`): `rule.condition.matches(state, caster_id,
  chosen_targets)` gates the reduction; when true, `cost =
  cost.reduced(rule.amount * rule.condition.multiplier(...))`
  (multiplier is `1` for both Phase-1 boolean conditions). So Python
  casts Gigastorm Titan for {3} less generic when the caster has cast
  another spell this turn, and Lashwhip Predator for {2} less when
  opponents control >=3 creatures.
- **Rust models NONE of it.** `CardPrinting`
  (`rust/src/cards.rs:4040-4171`, struct ends at `pub loyalty: i32`
  line 4170) has **no `cost_reductions` field**; the only mention in
  all of `rust/src/` is the deferral comment at `cards.rs:4180`
  (`ActivatedAbility` doc: "The richer Python fields — `sorcery_speed`,
  `cost_reductions`, `room_half`, `tier_threshold`,
  `activate_only_once` — are deferred to follow-up slices"). Rust has
  no `apply_cost_reductions` analogue; `cast_creature`
  (`state_ops_cast.rs:343-417`) reads `p.mana_cost.clone()`
  (`:364`) and pays exactly the printed cost via `pay_mana_cost`
  (`:371`) — no reduction layer. **Worse than warp:** Rust's Player
  struct (`state.rs:467-521`) has **no `spells_cast_this_turn`
  field** (and no per-turn spell-count analogue) — the
  `AnotherSpellCastThisTurn` condition has no state to read on the
  Rust side; this is a NEW Rust state field Phase 1 must add and
  maintain (§3.4(c)).
- **The bridge cannot carry it.** `CardDef`
  (`cross_engine.py:106-...`, "only the fields both engines understand
  from a parity standpoint") has **no cost-reduction field**;
  `build_rust_state`'s `printing_dict` emits no cost-reduction key;
  `_card_def_to_python_printing` constructs a `CardPrinting` with the
  default `cost_reductions=()`.

The drop is **asymmetric** (Python applies the reduction, Rust pays
full — no symmetric-bit-equality), AND it fires on the cast pipeline
the bench's `attack_all` strategy *always* drives (it plays creatures
to attack with them, so it WILL cast Gigastorm Titan / Lashwhip
Predator). The post-cast mana-pool / floating-mana / available-mana
state diverges on the **first cast of the card** → the bench's state
fingerprint mismatches immediately. There is no
`attack_all`-conditional "the strategy never triggers it" escape
hatch (contrast round-39 Ward: Ward only fires when a spell *targets*
the warded creature, which `attack_all` never does; here the
reduction fires on the always-driven cast). **This is correctly
§2-DECLINED today** (`COST_REDUCTION_SUBSTRATE_PLAN.md` §2 Class-2,
reaffirmed).

### 2.2 Post-Phase-1 verdict — bridge-CORRECT

Once Phase 1 lands the field on **both** the CardDef bridge AND Rust,
adds the Rust `spells_cast_this_turn` state + the two-condition
evaluator, AND Rust's cast pipeline applies the reduction under the
same condition Python does:

> **The spell-local boolean-condition cost-reduction path is
> bridge-CORRECT and complete for Gigastorm Titan / Lashwhip
> Predator.** Both engines compute the SAME reduced `ManaCost` at cast
> time (full printed cost minus `amount` generic when the boolean
> condition holds, full cost when it doesn't), debit the same mana
> pool, and reach the same post-cast state. There is **no residual
> silent mistranslation** — the divergence existed *precisely
> because* one engine reduced the cost and the other didn't; closing
> it on both sides removes the asymmetry entirely. The
> `legal_actions` action SET is unchanged by cost-reduction (unlike
> warp, which adds a `use_warp=true` variant — cost-reduction does
> NOT add an action, see §3.4); only the *cost paid* by the existing
> `CastSpell` action changes, identically on both engines.

**Caveats to flag forward (must hold for the post-Phase-1 claim):**

1. **The Rust `_can_cast` divergence is pre-existing and orthogonal —
   and cost-reduction interacts with it differently than warp.** Rust's
   `cast_spell_dict` emits CastSpell for every non-Land hand card
   regardless of mana availability (documented "Deliberate divergence",
   `state_ops_legal.rs` module docstring; Python gates on `_can_cast`).
   Because cost-reduction does NOT add a new action (it modifies the
   existing CastSpell's cost), the action-set asymmetry is *unchanged*
   by Phase 1 — the existing already-accepted base-CastSpell
   payability-gate asymmetry simply continues. **No new legal-emitter
   asymmetry is introduced** (contrast warp, which had to carefully
   mirror the no-`_can_cast` shape on its NEW emitter). The only thing
   Phase 1 must keep parity on is the *cost actually debited when the
   CastSpell resolves* — which both engines compute via the same
   reduction rule. (Python's `legal_actions` affordability probe ALSO
   calls `apply_cost_reductions` so a card that is only castable WITH
   the reduction shows up as legal in Python; Rust's emitter is
   unconditioned on payability anyway, so it already shows the card —
   the asymmetry is the *same* one the bench already tolerates for
   every base CastSpell, not a new one.)
2. **Fungal Colossus / Uthros / Sami MUST stay filtered until
   Phase 2/3.** The Phase-1 filter guardrail
   (`_printing_is_bridge_pure_cost_reduction_creature`, §3.7)
   positively rejects any printing with a non-empty
   `external_cost_reductions`, or any `cost_reductions` rule whose
   condition is NOT one of the two Phase-1 boolean conditions
   (`AnotherSpellCastThisTurn`, `OpponentsControlAtLeast`). This is
   the §2 guardrail's teeth — the negative pins in §4 enforce it.
   Fungal Colossus trips the condition-kind allowlist
   (`PerDifferentlyNamedLand` is not Phase-1); Uthros/Sami trip the
   `external_cost_reductions` non-empty check.
3. **`Player.spells_cast_this_turn` becomes a real production read on
   Rust.** Today Rust has no such field. Phase 1 adds it + the
   increment site (every cast bumps it) + the per-turn reset. This is
   a NEW Rust state field — the implementing agent must verify it is
   threaded through the state fingerprint / clone / CoW machinery
   (the round-61 SL discipline for new GameState/Player fields) and
   that the increment fires at the SAME logical moment Python's does
   (Python increments AFTER cost is paid — `NthSpellThisTurn`'s
   docstring `conditions.py:248-262` confirms "the cast pipeline
   increments AFTER cost is paid"; so when computing the reduction
   for the spell currently being cast, `spells_cast_this_turn`
   counts only *strictly previous* casts this turn, which is exactly
   why `AnotherSpellCastThisTurn` reads `>= 1`).

```rust
/// A spell-local cost-reduction rule. Mirrors Python's
/// `CostReduction` dataclass at `src/mtg_bot/cards/base.py:310`
/// (`amount: int`, `condition: Condition`). **cost-reduction
/// substrate Phase 1.** Phase 1 carries ONLY the two boolean
/// conditions sub-shape A uses; the bridge filter
/// `_printing_is_bridge_pure_cost_reduction_creature` positively
/// rejects every other shape so they never reach this struct in a
/// Phase-1 deckspec. `amount` is the unit generic reduction; for
/// Phase-1 boolean conditions the multiplier is implicitly 1
/// (Python: `Condition.multiplier` default `conditions.py:69-75`),
/// so the reduction is exactly `amount` generic when the condition
/// holds. Phase 2 adds a variable-multiplier path
/// (PerDifferentlyNamedLand); Phase 3 adds externals.
#[derive(Clone, Debug)]
pub struct CostReduction {
    pub amount: i32,
    pub condition: CostReductionCondition,
}

/// The Phase-1 boolean-condition subset of Python's structural
/// `Condition` grammar (`src/mtg_bot/effects/conditions.py`). Phase 1
/// ports EXACTLY two variants — the only two sub-shape A uses. The
/// full `Condition`-grammar port (variable multipliers, target-
/// dependent, predicate algebra) is Phase 2+ and is the reason
/// cost-reduction is strictly larger than warp (warp needed NO
/// condition grammar — see WARP_COST_PHASE1_DESIGN.md §0).
#[derive(Clone, Debug)]
pub enum CostReductionCondition {
    /// Python `AnotherSpellCastThisTurn` (`conditions.py:235-244`):
    /// the caster has cast >=1 OTHER spell this turn. Reads the new
    /// per-player `spells_cast_this_turn` counter (§3.4(c)) which
    /// counts strictly-previous casts (incremented AFTER cost-pay,
    /// mirroring Python — `NthSpellThisTurn` docstring
    /// `conditions.py:248-262`).
    AnotherSpellCastThisTurn,
    /// Python `OpponentsControlAtLeast(IsCreature(), n)`
    /// (`conditions.py:206-228`): some opponent(s) of the caster
    /// control, in total across all opponents, at least `n`
    /// permanents matching the creature predicate. Phase 1 hard-codes
    /// the `IsCreature` filter (the only predicate sub-shape A uses);
    /// the generic predicate algebra is Phase 2+.
    OpponentsControlCreaturesAtLeast { n: i32 },
}
```

### 3.4 Rust cast-cost hook — the KEY DIFF vs warp

> **This is where cost-reduction structurally DIFFERS from warp, and
> the most important section of the spec.**
>
> **Warp** offers an *alternative* cast: it adds a NEW
> `CastSpell{use_warp:true}` action to `legal_actions` (a new emitter
> helper `cast_spell_warp_dict`), and a NEW cast branch
> (`Action::CastSpell` `use_warp` arm → `cast_creature_warp`
> primitive) that pays a *different* `ManaCost` field
> (`warp_cost`). The warp action set is *bigger* (base + warp variant).
>
> **Cost-reduction does NOT add an action.** It modifies the cost of
> the *same* `CastSpell` action. There is no `use_warp`-style flag, no
> new legal-emitter variant, no new `Action` arm. The legal action SET
> is byte-identical with or without the reduction (verified: Python's
> `legal_actions` emits exactly one `CastSpell(card.id)` per
> castable spell whether or not it has a `cost_reduction` — the
> reduction only changes the cost the affordability probe computes,
> not whether the action is emitted; Rust's emitter is unconditioned
> on payability so it already emits the base CastSpell regardless).
> Therefore Phase 1 hooks the **existing** `cast_creature` primitive
> (`state_ops_cast.rs:343`), reducing `cost` between the
> `p.mana_cost.clone()` read (`state_ops_cast.rs:364`) and the
> `pay_mana_cost(&mut pool_copy, &cost)` spend
> (`state_ops_cast.rs:371`).

**What Phase 1 REUSES from warp's scaffolding** (re-verify post-merge —
see the ⚠ note at the top):

1. **The `Action::CastSpell` arm shape.** Warp Phase 1 changes the
   destructure at `state_ops_actions.rs:287-294` from `use_warp: _,`
   to `use_warp,` and branches `if use_warp { cast_creature_warp }
   else { cast_creature }`. Cost-reduction needs NO new branch — it
   stays on the `else { cast_creature }` path. **The reuse is: after
   warp lands, the `Action::CastSpell` arm already routes a plain
   (non-warp) creature cast to `cast_creature`; cost-reduction's
   change lives entirely INSIDE `cast_creature`, untouched by warp's
   branch.** If warp has NOT landed yet, the destructure is still
   `use_warp: _,` and routes unconditionally to `cast_creature`
   (`state_ops_actions.rs:333`) — cost-reduction's `cast_creature`
   change is independent of whether the warp branch exists. **Net:
   cost-reduction Phase 1 does NOT touch `state_ops_actions.rs` at
   all** (warp owns that file's CastSpell arm; cost-reduction's hook
   is one level down in `cast_creature`). This is a clean disjoint
   reuse — no merge conflict with the warp slice on that file.
2. **The cast-cost-branch *pattern*.** Warp's `cast_creature_warp`
   demonstrates the exact "read a different/modified `ManaCost`,
   then `pay_mana_cost` it" shape inside the cast primitive
   (`WARP_COST_PHASE1_DESIGN.md` §3.5(b) delta 1: "pay
   `printing.warp_cost` instead of `printing.mana_cost`"). Cost-
   reduction uses the SAME insertion point and the SAME
   `pay_mana_cost` call — it just computes
   `reduced = apply_cost_reductions_rust(printing, state, player_id,
   base_cost)` instead of swapping to a different field. If warp's
   `cast_creature_warp` lands first, the implementing agent should
   factor the shared "compute effective cost → pay it" tail so
   `cast_creature` and `cast_creature_warp` don't duplicate the spend
   logic (a clean refactor the warp spec already anticipates with its
   `cast_creature`-sibling structure).

**The cost-reduction hook (the actual `cast_creature` change):**

In `cast_creature` (`state_ops_cast.rs:343-417`), replace:

```rust

```

(line 364, inside the `Some(p) => { ... }` arm of the
`self.registry.lookup(printing_id)` match) — keep the
`!p.card_types.iter().any(|t| t == "Creature")` guard above it

```rust

```

**Borrow note:** `p` is a `&CardPrinting` borrowed from
`self.registry`; `apply_cost_reductions_rust` needs to read
`self.players[idx].battlefield` (for `OpponentsControlCreaturesAtLeast`)
and the new `spells_cast_this_turn` (for
`AnotherSpellCastThisTurn`). To avoid an aliasing conflict, the helper
must take the `cost_reductions` Vec *by clone* (or snapshot the two
scalar facts — `caster_spells_cast_this_turn: i32` and
`opponent_creature_count: i32` — before the registry borrow ends),
then compute the reduction with no live `&self.registry` borrow. The
implementing agent picks whichever the borrow checker accepts cleanly;
the cleanest is: clone `p.cost_reductions` into a local `Vec` while
the registry borrow is live (it is small — 1 rule for both Phase-1
cards), drop the borrow, then evaluate. Spec the helper:

```rust
/// Rust analogue of Python's `actions.apply_cost_reductions`
/// (`src/mtg_bot/actions.py:406`) restricted to the Phase-1
/// boolean-condition subset. Walks `rules` (cloned out of the
/// printing before the registry borrow ends), evaluates each
/// condition against current state, and returns `base` reduced by
/// the sum of matching `amount`s (generic only — `ManaCost::reduced`
/// mirrors Python's `ManaCost.reduced`, reducing the generic portion
/// and never the colored pips, `cards/base.py` `reduced`). Phase 1
/// has NO external scan (Phase 3) and NO variable multiplier
/// (Phase 2) — every Phase-1 condition contributes exactly `amount`
/// when it holds.
fn apply_cost_reductions_rust(
    rules: &[CostReduction],
    state: &GameState,
    caster_id: u8,
    base: ManaCost,
) -> ManaCost {
    let mut cost = base;
    for rule in rules {
        let holds = match &rule.condition {
            CostReductionCondition::AnotherSpellCastThisTurn => {
                state.player_by_id(caster_id).spells_cast_this_turn >= 1
            }
            CostReductionCondition::OpponentsControlCreaturesAtLeast
                { n } => {
                let mut count = 0i32;
                for obj in state.battlefield_iter() {
                    if obj.controller_id == caster_id { continue; }
                    if obj_is_creature(obj, state) { count += 1; }
                    if count >= *n { break; }
                }
                count >= *n
            }
        };
        if holds {
            cost = cost.reduced(rule.amount);
        }
    }
    cost
}
```

(`battlefield_iter` / `player_by_id` / `obj_is_creature` /
`ManaCost::reduced` — the implementing agent maps these to the live
Rust helper names at implementation time; `state.rs` exposes a
`player_by_id`-equivalent and the legal emitter already iterates the
battlefield with the `card_types.iter().any(|t| t == "Creature")`

`ManaCost.reduced` semantics exactly: clamp generic at 0, never touch

(c) **New Rust per-player `spells_cast_this_turn` state.** Rust's
`Player` (`state.rs:467-521`) has no spell-count field. Phase 1 adds:

- `pub spells_cast_this_turn: u32,` on `Player` (`state.rs:467`),

- **Increment site:** in `cast_creature` (`state_ops_cast.rs`), AFTER

## 9. §2 verdict

**CONFIRMED: Phase-1 sub-shape A (Gigastorm Titan + Lashwhip Predator,
spell-local boolean-condition `CostReduction` riders) is
bridge-correct once both engines compute the reduced cost
identically.** Both engines, post-Phase-1, compute the SAME reduced
`ManaCost` (full printed cost minus the rule's `amount` generic iff
the same boolean condition holds) at the SAME cast-pipeline moment,
debit the SAME mana pool, and the `legal_actions` action set is
UNCHANGED (no new action — the key structural advantage over warp).
**Nothing in Phase-1's scope is NOT bridge-correct**, with two flagged
forward dependencies that MUST hold (both have loud, not silent,
failure modes — §2 honest):

1. The new Rust `Player.spells_cast_this_turn` field MUST be (a)
   incremented at the bit-equivalent moment Python increments (post
   cost-pay) and (b) reset at the bit-equivalent per-turn boundary
   Python resets — the implementing agent MUST verify Python's exact
   reset site rather than assuming warp's cleanup hook (round-60-N1
   verified-live-signature discipline). A reset-site mismatch would
   mis-evaluate `AnotherSpellCastThisTurn` across the turn boundary.
   Pinned (§4 pin 6).
2. The Rust `ManaCost::reduced` MUST mirror Python's
   `ManaCost.reduced` exactly (clamp generic at 0, never touch
   colored pips). Pinned (§4 pin 4).

Both are construction obligations with explicit pins, NOT residual
silent mistranslations. The guardrail's positive allowlist + the
Rust-side hard-error on unknown `condition_kind` give the §2 decline
*teeth on both bridge sides* — a regression that admits a Phase-2/3
card fails LOUDLY (Rust `parse_printing` Err / Python bridge `raise`),
never silently pays the wrong cost. Per the "new code is right in
parity-gated replacements" / "oracle text fidelity" feedback: this
spec writes the Rust side to match Python's source-of-truth
cost-reduction semantics; any Phase-1 parity failure is a bug-finder
to fix on whichever side is wrong, not a reason to mirror a quirk.
