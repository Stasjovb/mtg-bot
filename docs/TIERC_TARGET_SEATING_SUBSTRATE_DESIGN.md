## 2. The deterministic target-selection rule (byte-equal-able across engines)

### 2.1 How Python's target selection resolves for these triggers TODAY (the source of truth)

Verified live, `actions.py:3206-3269` (the triggered-ability push
path, `_put_triggered_ability_on_stack`):

1. `effect.target_count_range()` → `(min_t, max_t)`. If `max_t == 0`
   the effect is untargeted; skip (not a target-seating consumer).
2. With `max_t > 0`: `legal = effect.legal_targets(state,
   controller_id)`. For both Sunset Saboteur and Exosuit Savior this
   resolves to `Effect.legal_targets` →
   `Effect._enumerate_for_filter` (`base.py:78-152`), which walks
   **`state.battlefield` in list order** appending each object whose
   `slot.filter.test(o, state)` passes (tagged `creature` /
   `planeswalker` / `battle` / `permanent`), THEN walks
   `state.players` in order appending eligible `("player", id)`. **The
   order of `legal` is therefore: battlefield Vec/insertion index
   ascending, then player order.**
3. `if not legal and min_t > 0:` → log "no legal targets; fizzles",
   `return False` (trigger NEVER goes on the stack — CR 603.3c /
   trigger removed for no legal target).
4. Else, per slot up to `max_t`: `if controller.agent is None:
   break`. **In the production-deck bench path `controller.agent is
   None` (verified live: `setup_matched_game_from_real_decks`
   players carry `agent=None`; `RealGameCombatAgent` does NOT
   override `choose_target`, and `Agent.choose_target` raises
   `NotImplementedError`).** So the loop breaks with
   `chosen_list == []`.
5. `if len(chosen_list) < min_t:` → log "no target chosen; fizzles",
   `return False`.

Net Python behavior with NO agent (the bench reality):
- **`count_min >= 1` (Sunset Saboteur):** the trigger **fizzles
  entirely** — it never reaches the stack.
- **`count_min == 0` (Exosuit Savior):** `0 >= min_t(0)` holds → the
  trigger goes on the stack with `targets=()` → the optional effect
  **resolves as a no-op** (`Bounce.resolve`/`PutPlusOneCounters.
  resolve` both early-`return` on empty `targets`).

This is NOT a deterministic-first pick today — it is a fizzle/no-op.
**That is precisely why the leaf is `_SAFE_TRIGGERS`-declined: Rust's
targeted effect arms (the `EquipToTargetCreatureYouControl`-style
first-eligible `bf.iter()` fallback, and the
`DealDamageAnyTarget`-family resolve-time scans) would pick a real
target and apply the effect, while Python fizzles/no-ops — a
guaranteed divergence.** The sub-substrate's job is to replace BOTH
sides' no-agent behavior with the SAME deterministic pick.

### 2.2 The canonical rule (the substrate makes this the no-agent default on BOTH engines)

> **The deterministic no-agent target for a SAFE triggered ability's
> first `TargetSpec` slot is: the battlefield object with the
> smallest `state.battlefield` (Python list) / per-player
> `battlefield` Vec insertion index that passes the slot filter; if
> the filter admits players and no battlefield object qualifies, the
> first non-`has_lost` player in `state.players` order that passes;
> if nothing qualifies and `count_min >= 1` → silent fizzle (trigger
> not pushed); if `count_min == 0` → push with no target (effect
> no-ops).**

This is byte-equal-able with **zero new ordering convention** because
it is the order BOTH engines already use:

- **Python** — `Effect._enumerate_for_filter` (`base.py:124-148`)
  literally produces `legal` in this order; `legal_targets[0]` IS this
  pick. This is exactly what the campaign's `_PickFirst*` shim family
  encodes (`tests/parity/_picker_shims.py`):
  `_PickFirstLegalTargetAgent` returns `legal_targets[0]`;
  `_PickFirstControlledCreatureAgent` /
  `_PickFirstOpponentTargetAgent` /
  `_PickFirstBattlefieldCreatureEitherSideAgent` each pick the
  smallest-bf-index filter-passing object. The substrate's Python side
  is "behave as if a `_PickFirstLegalTargetAgent`-equivalent were
  seated for safe triggered abilities", implemented WITHOUT an agent
  (a deterministic in-engine pick at `actions.py:3247`, gated to the
  safe-trigger path — §3.2).
- **Rust** — the `EquipToTargetCreatureYouControl` arm's `None`
  branch (`state_ops_resolve.rs:8995-9004+`) is the canonical
  precedent: `bf.iter().find_map(...)` over the controller's
  battlefield = first-eligible by Vec index. The ~15
  `DealDamageAnyTarget`-family arms (`state_ops_resolve.rs:6503`,
  `:6754`, `:6868`, `:6989`, `:7107`, `:7218`, …) all use "scan in
  ascending player index, first eligible Creature on bf, else the
  player". The substrate's Rust side seats the SAME first-eligible
  pick at *push* time (into `TriggerPayload.target_id`) so the
  resolve-time arm reads it via `current_resolve_payload_target_id`
  (the §3.3 path) — identical object to Python's `legal_targets[0]`.

**Tie-breaks / determinism guarantees (all already true on both
engines, verified):**
- *Object order*: `state.battlefield` is a single flattened list in
  Python (`game.GameState.battlefield`) and per-player `Vec`s in Rust
  scanned in ascending player index. The cross-engine harness keeps
  object ids + battlefield insertion order in lockstep (the
  `build_rust_state` registration order is the Python bf order — the
  invariant every existing trigger probe already relies on). So
  "smallest bf index passing the filter" names the SAME object on
  both engines.
- *Filter*: the slot filter is bridged structurally as part of
  lever-a (the per-card Effect's Rust variant carries the same
  filter); §3 requires the Rust resolve arm to apply the
  byte-identical predicate (`IsCreature & ControlledByOpponent` for
  Sunset Saboteur; `ControlledByYou & ~IsPlayer & ~IsSource` for
  Exosuit Savior).
- *Player fallback*: `state.players` order is fixed and shared
  (seat 0, seat 1); `has_lost`/`has_lost` excluded identically.
- *No RNG, no agent, no `PendingDecision`*: the pick is a pure
  function of (bf order, filter) — reproducible, hash-stable, and
  identical across engines by construction.

### 2.3 CR-correctness note (document in SEARCH_LIMITATIONS.md at implement time)

Real MTG picks the trigger's target when the ability is *put on the
stack* (CR 603.3d) by the ability's controller's *choice*. The
substrate replaces that choice with a deterministic first-legal pick
(no agent). This is the SAME deliberate divergence the campaign
already documents for every `_PickFirst*`-driven probe and the Rust
first-eligible resolve arms — it is consistent with the
campaign-wide "no-callback first-legal-target convention" (HANDOFF §6;
the rung-1 spec §3.4). The implementing Rust slice MUST add a
`docs/SEARCH_LIMITATIONS.md` entry: location
(`actions.py:_put_triggered_ability_on_stack` safe-trigger branch +
`state_ops_resolve.rs` push-target seat), what (deterministic
first-legal target for safe triggered abilities instead of a
controller choice), why OK (bench/parity context only — the
production-deck loader has no strategic agent; the pick is byte-equal
across engines, which is the property the bench measures), failure
mode (a strategically *better* target is never chosen — irrelevant to
parity; a non-first legal target is never reachable in the bench),
fix-scope (seat a real strategic agent in the bench loader — a much
larger, separate effort), impact (parity-positive; zero strength
claim).

## 3. Exact Rust mechanics

The substrate is **distinct from lever-a** (the per-card bespoke
Effect + bridge arm — the already-running Tier-A cadence) and
**distinct from lever-b's untargeted form** (the plain
`_SAFE_TRIGGERS` triple extension rung-1 ships for Arabella). It is a
THIRD mechanism: a *targeted-safe-trigger admission path* with a
deterministic push-time target seat. It reuses the EXISTING
`TriggerPayload.target_id` / `current_resolve_payload_target_id` /
`new_trigger_with_target` machinery (CE20 Slice 4, Equipment-equip) —
**no new `StackItem` field is required** (contrast Gate B'' for
spells, §4).

### 3.1 The push-time target seat — `dispatch_event` / `push_triggered_ability`

**File:** `rust/src/state_ops_resolve.rs`.

Live fact (`state_ops_resolve.rs:543-555`, `:656-673`):
`dispatch_event` builds a `firings` Vec of
`(source_id, controller, ability_index, effect, once_per_turn)` and
calls `push_triggered_ability`, which **always** uses
`StackItem::new_trigger` (`:666`, `target_id: None`). The Slice-1
docstring (`:646-655`) explicitly states *"No target selection …
deferred to Slice 4+"* — this substrate IS that deferred slice for
the safe-trigger path.

**Change:** `push_triggered_ability` grows an optional precomputed
target. The cleanest minimal seam (mirrors the `new_trigger` /
`new_trigger_with_target` pair already present at `state.rs:656` /
`state.rs:683` — VERIFIED live, exact names confirmed):

1. Add a private helper
   `fn first_legal_trigger_target(state, source_id, controller,
   effect) -> Option<u32>` next to `push_triggered_ability`. It
   returns `None` when `effect.target_count_range().1 == 0`
   (untargeted — every existing safe trigger; the helper is a no-op
   for them, preserving byte-identical behavior for Arabella and the
   20 live untargeted safe triples). Otherwise it scans **the same
   order Python's `_enumerate_for_filter` uses**: for each player in
   ascending seat index, each `obj` in `player.battlefield` Vec order,
   return the first `obj.id` whose printing+state passes the effect's
   first `TargetSpec` filter (the filter predicate is the per-card
   Rust variant's, supplied by lever-a — for Sunset Saboteur:
   creature ∧ controlled-by-an-opponent-of-`controller`; for Exosuit
   Savior: controlled-by-`controller` ∧ not-a-player ∧
   not-`source_id`); if the filter admits players and no bf object
   qualifies, the first non-lost player in seat order; else `None`.
2. In `push_triggered_ability`, gate the seat behind the
   safe-trigger admission so it ONLY fires for the cards lever-b
   admits (NOT every targeted trigger — that would change behavior
   for non-safe targeted triggers the engine handles elsewhere):
   compute `let tgt = first_legal_trigger_target(state, source_id,
   controller, &effect);` and push
   `StackItem::new_trigger_with_target(source_id, controller, effect,
   ability_index, tgt)` when `tgt.is_some()`, else `new_trigger`
   (unchanged path — preserves the fizzle/no-op semantics for the
   `count_min==0` no-eligible-target case, identical to Python's
   `targets=()` no-op; for `count_min>=1` with no eligible target the
   push must be **skipped entirely** to mirror Python's "fizzles,
   `return False`" — add the `count_min>=1 && tgt.is_none()` early
   return in `push_triggered_ability`).

> **`new_trigger_with_target` precedent re-verified live
> (`state.rs:683-700`).** It already constructs
> `TriggerPayload { effect, ability_index, target_id: Some(target_id)
> }`. Its docstring (`state.rs:674-682`) anticipates exactly this
> reuse: *"Non-equip targeted activations (future slices for targeted
> sacrifice, pump-target-creature activations, etc.) reuse this same
> constructor."* This substrate is one such reuse — no new
> constructor, no new `StackItem`/`TriggerPayload` field.

### 3.2 The Python mirror — the no-agent deterministic seat

**File:** `src/mtg_bot/actions.py`, `_put_triggered_ability_on_stack`
(verified `:3206-3269`).

The byte-equal Python change is at the `controller.agent is None`
branch (`:3247`). Today it `break`s (→ fizzle/no-op). The substrate
makes it, **only when the ability round-trips through
`_python_ta_to_safe_dict` as a target-seated safe trigger** (the
admission gate — keeps non-safe targeted triggers' existing
fizzle/no-op intact, so this is surgical and only the lever-b cards
change), pick `pool[0]` deterministically instead of breaking:

```python
if controller.agent is None:
    if _is_target_seated_safe_trigger(source, ability):  # §3.4 gate
        pick = pool[0]                                    # = legal_targets[0]
    else:
        break
```

`pool` at that point is `remaining` (the un-kind-filtered legal list
for `slot_kinds==()` — both lever cards have `slot_kinds==()`), whose
`[0]` is exactly `_enumerate_for_filter`'s first entry = the
canonical pick (§2.2). For Sunset Saboteur (`count_min=1`) this
yields one chosen target → the trigger goes on the stack with a real
target → `PutPlusOneCounters.resolve` adds the counter to that
object. For Exosuit Savior (`count_min=0`, optional) the substrate
