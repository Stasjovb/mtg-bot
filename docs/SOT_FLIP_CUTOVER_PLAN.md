# Source-of-Truth Flip Cutover Plan — the consolidated umbrella

## 0. Why this doc exists, and what it is NOT

The confirmed end-state architecture (see project `CLAUDE.md`, the
`HANDOFF_CONTINUOUS_PIPELINE.md` §6a full-game-trajectory framing, and
the `SUBSYSTEM_ROADMAP` cycle-2…6 folds) is: **Rust becomes the
authoritative rules engine** (action application, stack/priority, SBA,
layers, combat, every `Effect`); **Python retains only the NN stack**
(features / net / MCTS / AlphaZero / distributed), the **card
parser/loader**, and the **UI**, and calls *into* Rust for simulation.
The cross-engine parity campaign is simultaneously the *migration
mechanism* and the *flip-readiness evidence generator*.

Today the harness is **Python-drives / Rust-mirrors**: the action is
computed from the Python state (the source of truth), and the SAME
`action_dict` is replayed on BOTH engines via
`cross_engine.step_both`. At flip, the NN/MCTS sources its decisions
from **Rust's own enumeration** (`legal_decisions`) and applies them
via Rust, with Python no longer in the rules-evaluation loop.

**No consolidated "how and when do we actually flip
source-of-truth" document existed.** The criteria/sequence were
scattered across:

- the `POOL_PARITY.md` caveat ("whole-pool full-game-trajectory
  parity remains out of scope and is the campaign's open frontier"),
- the `SUBSYSTEM_ROADMAP.md` cycle-folds (the leverage map + revised
  Rust sequencing),
- the `SEARCH_LIMITATIONS.md` "Cross-engine legal-decision-set
  mana-payability asymmetry" entry (the decision-sourcing correctness
  gap),
- and the `HANDOFF_CONTINUOUS_PIPELINE.md` §6a framing.

**This doc is the INDEX + SEQUENCING + CRITERIA over those — it does
NOT duplicate or supersede them.** Each remains authoritative for its

- `docs/RUST_LEGAL_DECISIONS_MANA_AWARENESS_DESIGN.md` (the
  `legal_decisions` mana-awareness / decision-sourcing sub-spec —
  **authored concurrently by a sibling agent; referenced here as a

## 1. Flip-readiness criteria (the measurable gate)

The flip transfers source-of-truth from Python to Rust. It is sound
only if, *for the population the bot actually plays*, Rust's rules
evaluation is indistinguishable from Python's, AND the act of
*sourcing decisions from Rust* (not replaying a Python script) does
not itself introduce a divergence. The criteria are split into HARD
gates (must be objectively true) and JUDGMENT gates (recommended
thresholds + rationale, explicitly flagged as calls).

### C1 (HARD) — Decision-sourcing correctness landed

**Criterion.** The Rust `legal_decisions` enumerator must present the
SAME legal-decision set Python's `legal_actions` does, at every
priority point, over the loader-admitted population — specifically the
**mana-payability / alt-cost / target-satisfiability prune** must be
ported to Rust.

**Why this is the keystone HARD gate.** Today the two engines present
*different legal-decision SETS* whenever a hand card's cost is
un-payable: Python `legal_actions` is mana-aware (gates every
`CastSpell` on `_can_cast` → `can_pay_cost`,
`src/mtg_bot/legal.py:60-76`, call sites `:252-254` instant-speed /
`:383-385` sorcery-speed / `:631-657` ActivateAbility); Rust
`legal_decisions` enumerates **structurally** — its own module
docstring states it has no non-destructive `can_pay_cost` predicate
and "First-slice CastSpell emits for EVERY non-Land in hand regardless
of mana availability"
(`rust/src/state_ops_legal.rs:77-88`, "Deferred mana-affordability
check"; alt-cost flags `:90-101`). This is **proven
parity-benign TODAY only by construction**: the single-script-replay
contract interposes the Python (pruned) set as the SOLE script source,
so the Rust-only structural superset is unreachable as an agent choice
(`tests/test_cross_engine_legal_set_asymmetry.py`;
`docs/SEARCH_LIMITATIONS.md` "Cross-engine legal-decision-set
mana-payability asymmetry"). **The flip removes exactly that
construction** — at flip the NN/MCTS sources from
`rust.legal_decisions(pid)` directly, so the Rust-only structural
superset becomes *reachable as an agent choice*. An MCTS rooted on
Rust's enumeration would explore un-payable casts Python's engine
considers illegal; `step_both`-style cross-checks would raise on the
Python side (its `apply_action` invariants are stricter — the
documented failure mode), and single-engine Rust search would
over-enumerate. **This is the single must-land correctness fix before
flip.**

**Owner / dependency.** `docs/RUST_LEGAL_DECISIONS_MANA_AWARENESS_-
DESIGN.md` (sibling-authored sub-spec) owns the design + internals of
this fix. This doc does NOT re-specify it. The closure signal is
already wired: `tests/test_cross_engine_legal_set_asymmetry.py`'s
`..._mana_payability_asymmetry_characterized` is LOUD-on-closure (it
FAILS when Rust stops emitting the un-payable cast — that failure is
the intended signal to retire the SL entry, not a regression). The
`SEARCH_LIMITATIONS.md` entry's "Fix scope estimate" already names the
work (port a non-destructive `can_pay_cost` / `try_pay_mana_cost`-
with-rollback to `rust/src/state_ops_mana.rs`, gate the
`legal_decisions` CastSpell + ActivateAbility loops on it, land the
alt-cost flag detector for the kicker/warp/impending/Room-half
variants at the same time).

**Status: OPEN (hard flip-blocker).** Tracked by the sibling sub-spec.

### C2 (HARD) — Zero open Rust-side parity divergences of behavior class

**Criterion.** No CONFIRMED active Rust-side rules divergence may be
open at flip. A confirmed divergence is one where Rust's behavior
differs from the Python source-of-truth on a path the loader-admitted
population exercises (e.g. CFI-1: the stray `obj.counters = 0;` in
`Effect::DepressurizeEffect`'s destroy arm, `state_ops_resolve.rs`
~5969 — already fixed + merged `8a2a8d84`, pinned). The strict-xfail
divergence-pin trackers in `tests/test_probe_*` must all be passing
pins (no open `strict-xfail` representing an un-fixed divergence).

**Status at `d4014cdf`: CLOSED for the known set** — CFI-1 is fixed
(`8a2a8d84`). This criterion is a *standing* gate: every Rust slice's
§2 audit (`HANDOFF` §6 / `feedback_parity_new_code_is_right.md`) must
keep it true. **Re-verify at flip-time** that no open divergence pin
exists.

### C3 (JUDGMENT) — Effect+bridge byte-equal coverage over the
flip population

**Criterion (recommended threshold).** Source-of-truth may flip when
**Effect+bridge byte-equal coverage ≥ 95% of the LOADER-ADMITTED
population (deck-weighted), AND the remaining ≤5% is either residue
with accepted rationale (C5) or carries an explicit
play-it-anyway-safely rationale.**

**Critical distinction — which population.** There are two honest
denominators and they are NOT interchangeable:

- **Whole-pool** (all 475 EoE printings the parser claims):
  `docs/POOL_PARITY.md` reports **304/475 (64.0%) byte-equal at the
  Effect+bridge level** at `d4014cdf` (PROBED 96 = 20.2%;
  covered-by-construction 208; BLOCKED 171). This is the campaign's
  *open frontier* metric and is explicitly **NOT** the flip gate —
  the bot never plays the whole pool; it plays real 17lands decks
  through the loader.
- **Loader-admitted** (the printings
  `trajectory._printing_is_bridge_basic_land` /
  `_printing_is_bridge_simple_creature` /
  `_printing_is_bridge_simple_spell` / the warp / Lander-seating
  admit gates actually accept end-to-end): this is the population the
  bench tier exercises and the ONLY honest flip denominator.
  **This number is NOT currently reported anywhere as a single
  measured fraction** — see §1.1 (the measurability gap).

**Why a judgment call.** "95%" is a recommended bar, not a derived
constant. Rationale: (a) the bench tier (`HANDOFF` §6a) has been
**clean at scale** at this coverage (round-68 233 games / round-71 740
games / 7 disjoint archetype windows / 5 seed offsets, 0
FAIL_DIVERGENCE / 0 FAIL_EXCEPTION at the shipped cap-120) — i.e.
*empirically* the loader-admitted subset is already full-trajectory
byte-equal; (b) the residual is dominated by cards the loader DECLINES
to admit (so they never reach a real game under the current loader)
rather than admitted-but-divergent cards; (c) requiring 100% whole-pool
would block the flip indefinitely on permanent-residue cards
(Sothera et al.) that no planned substrate reaches and that the bot
*will never be dealt under the current loader*. The honest gate is
"the loader-admitted population is byte-equal, and the loader's
DECLINE set is itself the safety boundary". The recommended phrasing:
**flip when the bench tier is divergence-clean at scale over the
then-current loader-admit population AND the loader's admit gate is
the soundness boundary (a non-admitted card cannot enter a flipped
game)**.

### C4 (JUDGMENT) — Full-game-trajectory byte-equal evidence

**Criterion (recommended).** The bench tier
(`scripts/bench_trajectory_parity.py`, the *only* tier that exercises
real multi-turn games — `HANDOFF` §6a / `POOL_PARITY` caveat) must be
**0 FAIL_DIVERGENCE / 0 FAIL_EXCEPTION over ≥ ~700 games spanning ≥7
disjoint archetype windows and ≥5 seed offsets at the shipped
cap-120**, re-run on the flip-candidate commit (not inherited from an
older round).

**Why a judgment call + the honest caveat.** No tier claims the whole
pool is byte-equal in real full-game trajectories — that is explicitly
the campaign's open frontier (`POOL_PARITY` caveat, verbatim). The
bench is **scoped to the loader-admitted subset and depth-bounded**
(cap-120, round-72; a timed-out game yields zero divergence signal but
is not an engine failure). So C4 is *necessary trailing empirical
confirmation over what the loader admits*, NOT a whole-pool proof. The
recommended bar matches the already-achieved round-71 scale; the
judgment is "this scale of clean bench over the admit population is
sufficient evidence that the flipped engine plays identically on the
real deck distribution". A larger sweep is strictly better; this is
the floor.

### C5 (JUDGMENT) — Honest residue is N or accepted-with-rationale

**Criterion.** Every `genuinely_missing` residue entry
(`docs/residue_worklist.json`) is either (a) closed (shipped+bridged
Effect), or (b) explicitly ACCEPTED with rationale that it is a true
permanent-residue card no planned substrate reaches AND the loader
DECLINES to admit it (so it cannot enter a flipped game). At
`d4014cdf` the honest count is **7 genuinely_missing** (Lightstall
Inquisitor ×2 arms, Command Bridge, Astelli Reclaimer, Pain for All,
Meltstrider's Resolve, Roving Actuator) + **2 blocked_non_effect**
(Dauntless Scrapbot, Tractor Beam); **Sothera, the Supervoid** is a
verify-first-confirmed 8th `genuinely_missing` recommended by
`docs/SOTHERA_RESIDUE_INVESTIGATION.md` (not yet applied — the next
orchestrator resync applies it).

**Recommended disposition: ACCEPT all residue with rationale, do NOT
gate the flip on residue → 0.** Rationale: each residue card is
verify-first-confirmed (a) genuinely Effect-absent in Rust AND (b) NOT
reachable by any planned substrate (spell-card-bridge / warp Phase 2 /
Tier-C target-seating / `_SAFE_*` widening — see the Sothera
investigation §5 for the canonical disproof shape) AND (c) **loader-
DECLINED** — none is in any bench-admit gate, so a flipped engine is
never dealt it under the current loader. The flip soundness boundary
is therefore the loader admit gate, not residue-zero. Gating the flip
on residue → 0 would block indefinitely on cards the production bot
provably never plays. **The acceptance is conditional on C6 (the
loader admit gate is the enforced soundness boundary).**

### C6 (HARD) — The loader admit gate is the enforced soundness
boundary

**Criterion.** A card the loader does NOT admit MUST be unable to
enter a flipped (Rust-sourced) game — the admit gate must be a *hard*
boundary, not advisory. Concretely: the production deck loader path
(`trajectory.production_deck_to_deckspec` and the
`_printing_is_bridge_*` admit predicates) must reject any non-admitted
printing before it can be seated into a Rust-authoritative game, and
the flip wiring must NOT introduce a path that seats a non-admitted
card directly into Rust. This is what makes C5's "accept residue with
rationale" sound: the residue is unreachable because the loader fences
it out, not because we hope it won't come up.

**Status: PARTIALLY MEASURABLE.** The admit predicates exist and are
exercised by the bench. What is NOT yet pinned is an explicit
*flip-time invariant test* that a non-admitted printing raises (rather
than silently degrades) on the Rust-sourced path. Recommended: add
that pin as a cutover step (§2 step 2). **Open as a hard gate until
the invariant pin lands.**

### 1.1 The measurability gap (stated honestly)

**C3's loader-admitted denominator is NOT currently a single measured
number.** `docs/POOL_PARITY.md` measures the *whole-pool* Effect+bridge
fraction (304/475) and the bench tier reports *0/0.0%* under
"bridge-admitted & bench-exercised" — because that tier's precedence
requires the printing to fall through PROBED and covered-by-
construction first, so it structurally reads 0 even though the bench
*is* clean at scale (the bench's clean-at-scale signal lives in
`docs/bench_trajectory_parity_smoke.md`, NOT as a pool-parity tier
percentage). **Consequence:** C3 as a literal "≥95% of loader-admitted"
percentage is **unmeasurable with today's tooling**. The honest
flip-readiness signal is the *conjunction*: (C4) bench
divergence-clean at scale over the admit population + (C6) the admit
gate is a hard boundary. A measurement-tooling slice that reports
"fraction of the real 17lands deck pool that is end-to-end loader-
admittable, deck-weighted" would make C3 a single tracked number; it
does not exist today and is itemized as a follow-on (§4, the
loader-admit-completeness analysis). **Do not claim C3 is met by a
percentage until that tooling lands; rely on C4∧C6 in the interim and
say so.**

## 3. Rollback / safety story

**The reversibility invariant (must hold through the bake-in
period):** *Python's rules engine remains present, importable, and
step-for-step runnable as a shadow checker; the flip changes only
WHICH engine is authoritative, not whether Python can still evaluate a
step.* Concretely: do NOT execute Step 5/6 (deletion) until the
bake-in period closes green. While the invariant holds, rollback is a
**one-flag revert of the SoT designation** (Step 4 is a designation
switch, not a deletion) — the same shape as the project's other
reversible cutovers (cf. the runs.db Phase-2 "Producer dual-write
stays … a one-line revert restores previous behavior" pattern in
`CLAUDE.md`).

**Bad-flip detection (the tripwire).** During bake-in, Rust is
authoritative but Python runs as a lock-step shadow: every applied
action is also applied to a Python mirror and the post-step field
views are compared (the existing `cross_engine.compare_fields` /
`step_both` divergence machinery, repurposed — Rust now the driver,
Python the checker). ANY divergence, ANY Python-side `apply_action`
invariant raise (the documented C1 failure mode — Rust offered an
action Python considers illegal), or ANY bench FAIL_DIVERGENCE /
FAIL_EXCEPTION on the flipped commit is an automatic rollback signal.
This is exactly the signal the cross-engine campaign already
generates; the flip *keeps it running as a guard* rather than
discarding it.

**Revert procedure.** (1) Flip the SoT designation flag back
(Python authoritative). (2) The NN/MCTS decision source reverts to the
Python-derived script (Step 3's wiring must be behind the same flag —
a design constraint on the Step 3 wiring doc). (3) File the divergence
as a confirmed Rust-side parity bug (C2 class), fix under the standard
§2 discipline, re-run Steps 0/4. **Constraint on Step 3/4 design:**
the decision-source and SoT-designation switches MUST be a single flag
(or two coupled flags) so revert is atomic — a half-reverted state
(Rust enumerates, Python applies, or vice versa) is itself a
divergence surface and must be unrepresentable.

**Bake-in exit criterion (recommended judgment):** the shadow-checker
runs divergence-clean over a production-representative volume — the
same scale as the C4 bench bar (≥~700 games / ≥7 archetype windows /
≥5 seeds) PLUS a real distributed self-play/eval iteration
(`mtg_bot iterate`) completing with zero shadow-divergence. Only then
execute Steps 5/6 (the irreversible deletions).
