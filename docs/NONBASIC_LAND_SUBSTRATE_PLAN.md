# Non-basic land substrate — implementation + scoping plan

## 0. Why this doc exists

`docs/SUBSYSTEM_ROADMAP.md` (round-58 N2) data-ranked the **non-basic
land substrate** as the highest-leverage *clean* next lever: 23 cards,
**all 23 single-gated** (zero multi-gate residue → the yield is fully
realized in one closure), 34,575 cumulative 17lands decks, medium
scope. Those 23 are non-basic lands blocked from the production-deck
bench **only** because `_printing_is_bridge_basic_land`
(`src/mtg_bot/parity/trajectory.py:3202`) requires the `"Basic"`
supertype.

This doc scopes that closure **before** a future round implements it —
the round-57 residue-re-walk discipline (scope precisely; verify
first). The headline finding of the verify pass: **the roadmap's
"23 single-gated zero-Effect mana-only lands" framing is half right.
Only ~9 of the 23 are clean to admit as-is; the rest carry riders
(pay-life replacement, "enters tapped", Station, activated abilities,
Exalted, clone) that the *parser silently drops* — admitting them by
widening the supertype gate alone would ship a silent rules
simplification, not a clean unlock.** §2 is the honest audit.

## 2. Bridge-correctness audit (CRITICAL — honest verdict per sub-shape)

The §2 discipline (HANDOFF §2, round-42 I2): **only admit a shape
both engines model identically; decline silent-mistranslation paths;
do NOT recommend admitting a shape just because it raises the count.**

The dominant structural fact discovered in the verify pass:

> **The CardDef bridge has NO `enters_tapped` field, and Rust's
> `register_printing` (`rust/src/cards.rs`) has NO land
> `enters_tapped` path at all** — Rust lands are *always* untapped
> mana sources. The Python engine, by contrast, *does* honor
> `printing.enters_tapped` (`actions.py:1087`, 1092, 2992) and
> `enters_tapped_unless_any_player_life_at_most` (`actions.py:1097`).

This splits the 23 into three honest classes:

*derived* clean shape:

  Stomping Ground / Godless Shrine / Sacred Foundry with

  - **Verdict: bridge-CORRECT (engines agree byte-for-byte), but

### Phase 1 — `_SAFE_NONBASIC_MANA_LAND` admit, mana-only flat profile (the cheap clean win)

**Scope:** sub-shape A — 5 pay-life shocklands as untapped duals.
This is the largest bridge-correct sub-shape and the recommended

- **Filter change** (`src/mtg_bot/parity/trajectory.py`): add a new
  predicate `_printing_is_bridge_nonbasic_mana_land(printing)` and OR
  it into `_filter_deck_to_bridge_supported` (line ~3716-3719) +
  `_printing_to_card_def` (line ~3243) + the `pad_printing` guard
  (line ~3426 stays basic-only). The predicate is the §2 Class-1
  guardrail, verbatim:

  ```python
  def _printing_is_bridge_nonbasic_mana_land(printing) -> bool:
      if "Land" not in printing.card_types:
          return False
      if "Basic" in printing.supertypes:
          return False  # basic path owns these
      if not printing.produces or not (1 <= len(printing.produces) <= 2):
          return False
      if printing.activated_abilities:        return False
      if printing.triggered_abilities:        return False
      if printing.static_abilities:           return False
      if getattr(printing, "enters_tapped", False):        return False
      if getattr(printing, "enters_tapped_unless_any_player_life_at_most", None) is not None:
          return False
      if getattr(printing, "enters_as_copy_of_creature", None):
          return False
      if getattr(printing, "optional_copy_land_from_graveyard", None):
          return False  # Echoing Deeps' real clone field (round-59 verified)
      return True
  ```

  (Field names verified against `OracleParserCardSource` printings in
  round-59; the `getattr` defaults keep it robust if a field is
  absent.)

- **`_printing_to_card_def` arm:** a non-basic mana land becomes
  `CardDef(name=…, card_type="Land", mana_produced=tuple(sorted(printing.produces)))`
  — the *exact* shape the basic-land arm produces, just without the
  `"Basic"` supertype requirement. The dual-color auto-wire at
  `cross_engine.py:8845-8852` already iterates `mana_produced`, so a
  2-color land gets two `{T}: Add <c>` abilities on Python and a
  2-element `mana_produced` Vec on Rust. **No CardDef field change,
  no Rust change.**

- **Pin plan:** in `tests/test_trajectory.py` (or a new
