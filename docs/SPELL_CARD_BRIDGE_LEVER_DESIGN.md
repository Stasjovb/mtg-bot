# Spell-card-bridge lever — implement-ready design

## 0. Why this doc exists

`docs/EFFECT_UNCOVERED_TIERA_MINISPECS.md` §1.1 found the honest
two-layer split: closing a Tier-A bespoke Rust `Effect` + bridge arm
(a) **drains the pool-parity Effect-uncovered bucket** (the card's
emitted classes become a subset of `covered_python_class_set()`) and
(b) makes that Effect **genuinely cross-engine-probeable** via the
synthetic-stack-resolve driver on the REAL printing — BUT (c) the full
Instant/Sorcery card **stays loader-gated**, because the production-deck
bench loader has NO Instant/Sorcery admit path. The mini-specs §4/§5
recommended a single shared ~1-round "spell-card-bridge lever"
(`_printing_is_bridge_simple_spell` + a `CardDef` spell arm) that flips
all 31 Tier-A cards from drop→admit at once, sequenced after 3-5 Tier-A
Effects close. This doc is that lever's precise design — AND its honest
cross-check, because **verify-first surfaced that the lever is larger
than the mini-specs' "~1 round" estimate** (§7).

## 1. Exactly what is missing today — the two gates (verified live, HEAD `6568c346`)

### 1.1 Gate A — the loader filter has no spell predicate

`_filter_deck_to_bridge_supported` (`trajectory.py:3924`) is the
production-deck loader's admit gate. Its OR-chain
(`trajectory.py:3945-3949`, verified verbatim):

    or _printing_is_bridge_nonbasic_mana_land(printing)

Three predicates, all land/creature; **no spell predicate**.
`_printing_is_bridge_simple_creature` (`trajectory.py:3231`)
**positively rejects any spell** at **`trajectory.py:3305`** (verified
verbatim):

```python

```

Every one of the 8 Tier-A cards has a non-None `spell_effect` (§1.4
verify-first table) → none is admitted by any existing predicate.
`_printing_to_card_def` (`trajectory.py:3444`) has three arms
(basic-land `:3454`, nonbasic-mana-land `:3461`, simple-creature
`:3479`) and a terminal `raise ValueError` (`:3516`); **no spell arm**.

### 1.2 Gate B — the CardDef bridge cannot carry a spell

`CardDef` (`cross_engine.py:106`, `@dataclass(frozen=True)`) is
documented (`cross_engine.py:129`): `card_type: str  # "Land" or
"Creature"` — **no spell variant, no `spell_effect` field**. The
materializers drop the spell on BOTH sides:

- **Python side:** `_card_def_to_python_printing` (`cross_engine.py
  :8842`) constructs `CardPrinting(...)` (`:8953-8971`) with **no
  `spell_effect=` argument** → it defaults to `None`. A spell CardDef
  would round-trip as an effectless husk.
- **Rust side:** `build_rust_state` (`cross_engine.py:8531`) builds
  `printing_dict` (`:8550-8561`) with a hardcoded **`"effects": []`**
  (`cross_engine.py:8560`) and no spell-effect key. Rust's
  `parse_printing` → `printing.effects` is empty; the Rust resolver
  (`state_ops_resolve.rs:10588`, `Some(printing) => printing.effects
  .clone()`) finds nothing to apply.

### 1.3 Gate B' — the Rust *cast* path silently no-ops a spell

Even if Gate A/B were widened naively, the Rust `Action::CastSpell`
arm (`state_ops_actions.rs:287-334`, verified) routes **unconditionally
to `cast_creature`** (`state_ops_actions.rs:333`):

```rust
let player_id = slf.borrow().priority_player;
slf.call_method1("cast_creature", (card_id, player_id))?;
```

`cast_creature` (`state_ops_cast.rs:343`) **returns `Ok(false)` for any
printing without `"Creature"` in `card_types`** (`state_ops_cast.rs
:361-363`, verified verbatim):

```rust
if !p.card_types.iter().any(|t| t == "Creature") {
    return Ok(false);
}
```

So `apply_action(CastSpell{instant})` on Rust is a **silent no-op**
(no mana paid, card stays in hand, no stack push) while Python's
`_cast_spell` pays mana, pushes a `StackItem`, and (post-resolve)
`spell_effect.resolve(...)` then `_send_to_graveyard_or_library`
(`actions.py:2780-2790`, verified). **This is a guaranteed asymmetric
divergence on the cast pipeline the bench always drives** — the same
class as the round-62 N2 warp `use_warp:_` discard. The spell-card
lever is therefore NOT a Python-bridge-only filter widen; it is a
Rust-substrate slice (Gate B' is the load-bearing piece, exactly like
warp's `Action::CastSpell` warp branch).

### 1.5 Gate B'' — targeted-spell target binding is asymmetric

Python's `legal.py` emits `CastSpell(card.id)` (`legal.py:244,363`)
**without bound targets**; it gates emission on
`_targets_are_satisfiable` (`legal.py:79-108`, CR 601.2c — ≥`min_t`
legal targets must exist) and binds the actual target later via a
separate target-selection `Decision` driven by
`controller.agent.choose_target` (the canonical campaign convention;
~30 cross-engine probes already exercise it for *triggered/activated*
effects — `cross_engine.py:529,620,1280,...`). Rust's spell legal
emitter (`state_ops_legal.rs:994-1022` sorcery pass + the instant-speed
pass) emits `cast_spell_dict` for *every non-Land hand card* with **no
payability gate and no `_targets_are_satisfiable` gate** (the
documented "Deliberate divergence" — Rust has no `_can_cast`). For a
*targeted spell*, Python additionally won't emit the cast when targets
are unsatisfiable; Rust will. And the *resolve* of a targeted spell
needs the chosen target threaded to `spell_effect.resolve(state,
controller, targets)` (Python `actions.py:2783`) vs Rust's
`current_resolve_payload_target_id` swap (`state_ops_resolve.rs
:10543-10555`, today only populated for `TriggeredAbility` stack items,
NOT spell stack items). **The targeted-spell cast→target→resolve path
is the genuinely new substrate this lever needs** — and it is the part
the "~1 round" estimate underweighted.

## 2. The §2 bridge-correctness audit — which spell sub-shapes the lever can carry

The §2 discipline (HANDOFF §2, round-42 I2): admit ONLY shapes both
engines model identically; decline silent-mistranslation paths. The
lever's `_printing_is_bridge_simple_spell` predicate is a **positive
allowlist guardrail** (the round-59 `_printing_is_bridge_nonbasic_mana
_land` precedent). A spell sub-shape is bridge-correct iff:

1. **`spell_effect` is a covered+bridged Effect** — i.e. its emitted
   Effect classes ⊆ `covered_python_class_set()` AND each has a live
   Rust `Effect::*` variant + a `_ta_dict_to_python_effect` bridge arm.
   (This is precisely the per-card Tier-A close the round-64 mini-specs
   ships first; the lever's guardrail *gates on the close having
   landed* — a Tier-A card admitted before its Effect's Rust variant +
   bridge arm exists would silently mistranslate to an effectless
   spell. The guardrail is the §2 teeth: it queries the live covered
   set, NOT a hardcoded card list.)
2. **card_types ⊆ {Instant, Sorcery}** — no permanent-spell riders
   (Aura attach, ETB, Room, clone — those are other substrates).
3. **No alt-cost / mode the deterministic bridge can't round-trip:**
   `x_pips == 0`, `kicker_cost is None`, `warp_cost is None`,
   `impending_cost is None`, not `ModalChooseOne`,
   `additional_cost_choice` absent (Close Encounter — §4),
   `room_halves` empty.
4. **Targeting the deterministic-first convention covers:** the
   spell's `target_slot_kinds()` are kinds the campaign's
   first-legal-target convention already drives byte-equal (the
   no-callback first-creature/first-permanent rule, established Monoist
   r51 / used by ~30 existing probes). Verify-first: all 7 ready
   Tier-A slots are `()` (single implicit creature/permanent target)
   or `('my_creature','creature')` (Diplomatic Relations — the
   two-independent-slot grammar, Monoist-r51 precedent). No
   `legal_targets` shape outside that convention is admitted.

### 2.1 Bridge-correct once the lever + the card's Effect close land

The 7 ready Tier-A cards (Radiant Strike, Seedship Impact, Orbital
Plunge, Depressurize, Focus Fire, Biosynthic Burst, Diplomatic

### 3.4 Gate B'' — single-target binding on the spell StackItem

**File:** `rust/src/state_ops_cast.rs` (in `cast_spell_noncreature`)
+ `rust/src/state_ops_resolve.rs` (the spell-resolve arm).

Python binds the target via a separate `choose_target` decision and
threads `item.targets` into `spell_effect.resolve(state, controller,
targets)` (`actions.py:2783-2785`). The deterministic-first-target
convention (the no-callback campaign rule, ~30 existing probes) picks
the first legal target. For the lever's Phase 1 (single target,
`target_slot_kinds()==()`):

- In `cast_spell_noncreature`, after pushing the spell `StackItem`,
  compute the **first legal target** for the spell's effect using the
  same deterministic-first scan the per-card Effect resolve arms use
  (the round-64 mini-specs' "deterministic first-creature/first-
  permanent" convention — e.g. `bf_iter::bf_iter_etb_sorted`), and
  store it on the stack item's target field (the `StackItem` carries
  `current_resolve_payload_target_id`-equivalent plumbing — verify the
  live `StackItem` struct `state.rs:596-610` has a target slot; if
  spell stack items don't carry one yet, this is the genuinely-new
  field the lever adds: a `target_obj_id: Option<u32>` on `StackItem`,
  defaulted `None`, set here for spells).
- In `resolve_top_of_stack`'s spell arm, swap that target into
  `current_resolve_payload_target_id` for the `apply_effect` loop
  (mirroring the triggered-ability target swap at `state_ops_resolve
  .rs:10543-10544`, which today only runs for `TriggeredAbility`).
  This makes the per-card bespoke Effect arms (which the round-64
  round ships, reading the target via the same swap) resolve byte-
  equal whether driven by a trigger OR a spell cast.

**This is the crux the "~1 round" estimate underweighted:** Gate B''
requires either confirming the live `StackItem` already carries a
spell target slot, or adding one + wiring the resolve-time swap for
`StackItemKind::Spell`. It is shared infrastructure (every targeted

    """True iff a CardPrinting is a PURE single-target Instant/Sorcery
    the spell-card-bridge lever round-trips byte-equal across engines.

    Spell-card-bridge lever, **phase 1** (round-66+; spec at
    ``docs/SPELL_CARD_BRIDGE_LEVER_DESIGN.md`` §3).

    Motivating set: the 6 single-target Tier-A spells whose bespoke
    Effect close has landed (Radiant Strike, Seedship Impact, Orbital
    Plunge, Depressurize, Focus Fire, Biosynthic Burst). Diplomatic
    Relations (2-slot grammar) is Phase 2; Close Encounter (additional-
    cost-choice + warp) is §2.2-declined Tier-C.

    The §2 teeth: it admits ONLY a spell whose `spell_effect` is a
    COVERED+BRIDGED effect (queried against the live covered set, NOT
    a hardcoded list), single-mode, no X / kicker / warp / additional-
    cost-choice, with a target shape the deterministic-first
    convention drives byte-equal. Every other spell shape stays
    filtered (the decline set, §2.2).
    """
    if not (
        "Instant" in printing.card_types
        or "Sorcery" in printing.card_types
    ):
        return False
    if "Creature" in printing.card_types:
        return False  # permanent-spell rider — other substrate
    se = printing.spell_effect
    if se is None:
        return False
    # Phase-2+ / declined shapes — positively rejected (the teeth):
    if printing.mana_cost is not None and getattr(
        printing.mana_cost, "x_pips", 0
    ):
        return False
    if printing.kicker_cost or printing.impending_cost:
        return False
    if printing.warp_cost is not None:
        return False
    if printing.room_halves:
        return False
    from mtg_bot.effects.combinators import ModalChooseOne
    if isinstance(se, ModalChooseOne):
        return False  # modal — later phase
    # Additional-cost-choice (Close Encounter): the effect reads
    # state.resolving_additional_cost_choice_id — no Rust analogue.
    # Detected structurally via the effect's covered-set membership
    # below (CloseEncounterEffect is NOT in the covered+bridged set
    # unless an additional-cost-choice substrate ships it) AND
    # explicitly via the card's additional-cost marker if the live
    # printing exposes one (verify at implement time).
    # Phase-1 single-target only — Phase 2 widens to 2-slot:
    min_t, max_t = se.target_count_range()
    if (min_t, max_t) != (1, 1):
        return False  # Phase 1 = exactly one required target
    if se.target_slot_kinds():
        return False  # heterogeneous-slot grammar is Phase 2
    # The load-bearing §2 gate: the effect must be a COVERED + BRIDGED
    # Effect (its emitted classes subset of the live covered set AND
    # each has a _ta_dict_to_python_effect bridge arm + Rust variant).
    # This is what makes the lever gate on the per-card Tier-A close
    # having LANDED — admitting a card before its Effect's Rust+bridge
    # exists would silently mistranslate to an effectless spell.
    # Use the existing covered-set query the pool-parity gate uses
    # (verify the exact helper at implement time —
    # `covered_python_class_set()` / the round-64 effect-uncovered
    # classifier; the predicate must NOT hardcode a card-name list).
    if not _spell_effect_is_covered_and_bridged(se):
        return False
    return True
