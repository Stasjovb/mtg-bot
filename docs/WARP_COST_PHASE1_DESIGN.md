# warp_cost Phase-1 — implement-ready spec (the 3 single-gated warp cards)

## 0. Why this doc exists

`docs/WARP_COST_SUBSTRATE_PLAN.md` (round-61 N2) established:
warp_cost is the agreed **first cost-mechanic Rust substrate** —
sequence it BEFORE Aura-attachment (~24× single-gate deck-count:
15,436 vs 633) and BEFORE cost-reduction Phase 1 (warp is the lighter
member: a fixed alternative `ManaCost` + a deterministic end-step
exile, NO `Condition`-grammar port). It is NOT a filter-widen win:
`CardDef` has no warp field, Rust's `CardPrinting` has no `warp_cost`
field, Rust's `legal_actions` never emits `use_warp=True`, and
`Action::CastSpell` discards `use_warp` (`use_warp: _`). The drop is
**asymmetric** and fires on the cast/legal pipeline the bench always
drives — admitting any of the 3 single-gated cards by widening the
filter ships a *guaranteed* inter-engine divergence visible at
`legal_actions`. The real closure is a multi-round Rust substrate.

This doc is that substrate's **Phase-1 spec**: the precise CardDef
field, the Rust `CardPrinting` field + serde, the `legal_actions`
emitter site + condition, the `Action::CastSpell` warp branch + the
end-step exile, the bidirectional bridge arms, the pin plan, the
genuine-real-EoE-probe plan, the per-phase EoE-pool delta, the phase
boundaries, and the §2 audit confirming the path is bridge-correct
once both engines emit+pay it. A round-63 Rust agent should be able to
execute Phase 1 from §3 without re-deriving the design.

### 2.1 The pre-substrate state (the divergence Phase 1 closes)

Verified live:

  `legal.py:262-271` (instant-speed) and `legal.py:392-401`
  (sorcery-speed) emit `CastSpell(card.id, use_warp=True)` when
  `card.printing.warp_cost is not None` and the warp cost is payable.
  `actions.py:1393-1436` (`_cast_spell`'s hand branch) pays
  `effective_warp_cost(...)` instead of `mana_cost`, sets
  `card.cast_via_warp=True`, flips `state.spell_warped_this_turn=True`,
  and `actions.py:1550-1559` appends a `WarpExileSelf` delayed trigger
  to `state.delayed_triggers` (`fire_at_turn = turn_number + offset`).
  At end step `turn.run_delayed_end_step_triggers` (`turn.py:773`)
  fires it; `WarpExileSelf.resolve` (`effects/generic/exile.py:150-172`)

  `obj.cast_via_warp=False`. The exiled card is then re-castable from

  `warp_additional_life_cost` / `warp_castable_from_graveyard`

### 2.2 Post-Phase-1 verdict — bridge-CORRECT

Once Phase 1 lands the field on **both** the CardDef bridge AND Rust,
AND Rust's `legal_actions` emits the `use_warp=true` variant under the
same condition Python does, AND Rust's `Action::CastSpell` pays
`warp_cost` + schedules the end-step exile + supports the
exile-recast:

> **The fixed-`ManaCost` warp path is bridge-CORRECT and complete for
> Red Tiger Mechan / Bygone Colossus.** Both engines emit the same
> action set (base CastSpell + `use_warp=true` CastSpell when warp
> cost payable), pay the same `warp_cost`, set `spell_warped_this_turn`
> at the same site, schedule the exile for the same end step, and
> offer the same exile-recast at normal cost on a later turn. There is
> **no residual silent mistranslation** — the divergence existed
> *precisely because* one engine modeled warp and the other didn't;
> closing it on both sides removes the asymmetry entirely.

**Caveats to flag forward (must hold for the post-Phase-1 claim):**

1. **The Rust `_can_cast` divergence is pre-existing and orthogonal.**
   Rust's `cast_spell_dict` emits CastSpell for *every* non-Land hand
   card regardless of mana availability — Rust has no `_can_cast`
   payability gate (documented "Deliberate divergence" in
   `state_ops_legal.rs`'s module docstring; Python gates on
   `_can_cast`). The Phase-1 spec **must mirror this exactly**: the
   Rust warp emitter is gated on `printing.warp_cost.is_some()` *only*
   (NOT on warp-cost payability), exactly as the base CastSpell
   emitter is unconditioned on `mana_cost` payability. This keeps the
   warp emitter's gating consistent with the surrounding emitter — the
   bench's existing parity harness already tolerates the
   payability-gate asymmetry for base CastSpell, so the warp variant
   inherits the same already-accepted shape. (If Phase 1 instead gated
   the Rust warp emitter on payability, it would introduce a NEW
   asymmetry the base emitter doesn't have.) The bench's deckspec
   loader admits the warp card; the harness drives it; both engines
   offer the warp variant whenever `warp_cost` is present.
2. **Timeline Culler MUST stay filtered until Phase 2.** The Phase-1
   filter guardrail (`_printing_is_bridge_pure_warp_creature`,
   §3.7) positively rejects any printing with
   `warp_additional_life_cost != 0` OR `warp_castable_from_graveyard`
   OR any other blocking feature. This is the §2 guardrail's teeth —
   the negative pins in §4 enforce it.
3. **`state.spell_warped_this_turn` becomes a real production write
   on Rust.** Today it is substrate-only (the round-61 SL pin: only
   the test `set_void_flags` writes it). Phase 1's warp-cast branch
   sets it — closing the SL pin's "no production write site". The
   `Effect::ConditionalIfVoid` consumer
   (`state_ops_resolve.rs`) already reads it via `is_void_active`, so
   this is a *positive* parity gain, not a new risk — but the
   implementing agent must update the SL pin (§3.8).

### 3.2 CardDef `warp_cost` bridge field

**File:** `src/mtg_bot/parity/cross_engine.py`, the `CardDef`

```python

    # warp alt-cost (EoE — Red Tiger Mechan {1}{R}, Bygone Colossus
    # {3}). Reuses the SAME (generic, colored) codec as
    # `mana_cost_generic` / `mana_cost_colored` — frozen, bridge-

    # pre-Phase-1 CardDef omits it, the registry-dict builder then
    # omits the `warp_cost` key and the Rust parser maps that absence
```

**Design note (verified against the live `mana_cost` codec):** CardDef
already represents a mana cost as **two scalar fields**
(`mana_cost_generic: int`, `mana_cost_colored: tuple[tuple[str,int],...]`)
— NOT a `ManaCost` object (CardDef is a frozen dataclass; a nested
`ManaCost` would still be hashable but the existing convention is the
flat-pair shape, and `build_rust_state` builds the registry mana dict
from exactly those two fields at `cross_engine.py:8557-8559`). Phase 1
**reuses that exact codec** for `warp_cost`. The separate `has_warp:
bool` disambiguates "no warp" from "warp cost {0}" (a free warp — no
EoE card has one today, but the explicit flag keeps the bridge honest
and matches Python's `warp_cost is not None` semantics, which a
`(0, ())` tuple alone could not express).

```python
def _printing_is_bridge_pure_warp_creature(printing) -> bool:
    """True iff a CardPrinting is a PURE fixed-`ManaCost` warp creature
    the Phase-1 warp substrate round-trips byte-equal across engines.

    Phase-6 warp_cost substrate, **phase 1** (round-63; spec at
    ``docs/WARP_COST_PHASE1_DESIGN.md`` §3, written round-62 N2).

    Motivating set: Red Tiger Mechan ({1}{R} warp, {3}{R} normal),
    Bygone Colossus ({3} warp, {9} normal) — both Artifact Creatures,
    warp is the ONLY blocking feature, no life rider, hand-only, no
    graveyard recursion. The §2 Class-1 guardrail: it admits ONLY the
    pure fixed-cost profile and MUST reject Timeline Culler
    (`warp_additional_life_cost=2`, `warp_castable_from_graveyard` —
    Phase 2) and every multi-gated warp card (static / Effect-
    uncovered — never flips on warp alone).
    """
    if "Creature" not in printing.card_types:
        return False
    if printing.power is None or printing.toughness is None:
        return False
    if printing.warp_cost is None:
        return False
    # Phase-2 riders — positively rejected (the §2 guardrail teeth):
    if getattr(printing, "warp_additional_life_cost", 0):
        return False
    if getattr(printing, "warp_castable_from_graveyard", False):
        return False

    # _printing_is_bridge_simple_creature (the 7 multi-gated warp
    # cards trip one of these and stay filtered):
    if printing.keywords and not printing.keywords.issubset(_SAFE_KEYWORDS):
        return False
    if printing.triggered_abilities:
        for ta in printing.triggered_abilities:
            if _python_ta_to_safe_dict(ta) is None:
                return False
    if printing.activated_abilities:
        return False
    if printing.static_abilities:
        return False
    if printing.spell_effect is not None:
        return False
    if printing.kicker_cost or printing.impending_cost:
        return False
    if printing.room_halves:
        return False
    if printing.loyalty is not None:
        return False
    if printing.cost_reductions or printing.external_cost_reductions:
        return False
    if printing.station_threshold:
        return False
    if getattr(printing, "dynamic_pt_formula", None) is not None:
        return False
    if getattr(printing, "ward_cost", None) is not None:
        return False
    try:
        _parse_mana_cost_string(printing.mana_cost_str or "")
        _parse_mana_cost_string(printing.warp_cost_str or "")
    except ValueError:
        return False
    return True
```
