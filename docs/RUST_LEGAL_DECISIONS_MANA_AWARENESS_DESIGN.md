# Rust `legal_decisions` mana-awareness — implement-ready spec (the SoT-flip-blocking non-destructive `can_pay_cost` predicate)

## 0. Why this doc exists, and the strategic context (the WHY)

`docs/SEARCH_LIMITATIONS.md:5347` ("Cross-engine legal-decision-set
mana-payability asymmetry") records an **ACCEPTED divergence with
rationale**: Python `legal.py:legal_actions` is mana-aware (it never
enumerates an un-payable cast / ability), Rust
`state_ops_legal.rs:legal_decisions` enumerates structurally. Today
that divergence is **benign by construction** because every
cross-engine harness uses the **observation-driven single-script-replay
contract** — the action is computed from the Python state (the source
of truth) and the *same* `action_dict` is replayed on both engines via
`cross_engine.step_both`. No cross-engine path sources an agent choice
from `rust_state.legal_decisions(pid)` (verified live:
`cross_engine.py:10238-10242` — "PassPriority is the only action both
engines can drive trivially without needing legal-action enumerator
parity ... that's the next slice's parity surface"). The regression
pins for this live in `tests/test_cross_engine_legal_set_asymmetry.py`
(3 tests, characterization + canonicalization + negative control).

**The strategic context — this is SoT-flip critical path.** The
end-state of the cross-engine refactor is **Rust as the AUTHORITATIVE
rules engine**, with Python retaining only the NN stack (Python calls
into Rust). At SoT-flip the harness contract **inverts**: the NN/MCTS
will source decisions from Rust's OWN `legal_decisions` enumeration
instead of replaying a Python-derived script. At that point, Rust
offering structurally-legal-but-UNPAYABLE casts (that Python never
enumerated) stops being "benign by construction" and becomes a **REAL
correctness defect**:

- The policy head would score, and PUCT would expand, illegal-by-mana
  actions. Self-play trajectory data would contain "moves" no legal
  agent could ever make. The value target would be polluted by
  branches that the engine, on `apply_action`, must reject or
  mis-handle.
- The asymmetry is **load-bearing on the flip** and has **no
  implement-ready spec today** — only the accepted-divergence note.
  This doc is that spec.

This doc is the implement-ready Rust design (WARP_COST_PHASE2 rigor)
for making Rust's `legal_decisions` mana-aware so it is correct when
it becomes the authoritative decision source. It covers: (1) the EXACT
verified surface of the asymmetry — corrected with live evidence
(it is **narrower than the SL note states**); (2) the non-destructive
`can_pay_cost` predicate design (the SL note's named core problem);
(3) the precise `legal_decisions` change + the parity contract (what
it must STILL emit so it does not over-prune); (4) a phased,
parity-NEUTRAL incremental landing path; (5) the pin/probe plan + the
gate + the bench/parity delta + the sub-slice verdict; (6) the
SoT-flip sequence position + dependencies.

### 1.3 The asymmetry, stated precisely (the parity contract)

At any priority point, for each card `c` in the priority holder's hand
(or warped exile object):

- **Python** emits a `CastSpell(c)` iff `_can_cast` (mana payable via
  pool + auto-tapped untapped lands + optimistic convoke/sac-for-mana)
  AND `_targets_are_satisfiable` AND `_additional_costs_payable`
  (and, for warp, `p.life > warp_additional_life_cost`).
- **Rust** emits a `cast_spell` dict for `c` iff it is a non-Land of
  the right speed (structural only).

So Rust's CastSpell set is a **structural SUPERSET** of Python's
mana-/target-/cost-pruned set. The **parity contract** the fix must
honor: after the fix, `RustCastSpellSet ⊇ PythonCastSpellSet` must
become `RustCastSpellSet == PythonCastSpellSet` **on the 5 live Rust
axes** — no narrower (would OVER-prune: drop a cast Python offers →
the harness would replay a Python-sourced action Rust no longer
considers legal → `step_both` raises), no broader (the defect).
"Equal on the 5 live axes" is the exact, testable contract; the
non-live Python axes (kicker/impending/granted-warp/Room/X/grave-warp)
stay a separate deferred surface and are NOT in scope (§1.4).

## 2. The non-destructive `can_pay_cost` predicate (the SL note's named core problem)

> The SL note (`SEARCH_LIMITATIONS.md:5380-5384`,
> `state_ops_legal.rs:77-88`) names the core problem exactly: *"Rust's
> `state_ops_mana.rs` has only the destructive
> `pay_mana_cost(player_id, cost_dict)` primitive — no non-destructive
> `can_pay_cost` predicate exists yet."* §2 specifies that predicate.

### 2.1 Where it goes + signature

Add to `rust/src/state_ops_mana.rs` (the home of `pay_mana_cost`; the
cost-pay logic the predicate must shadow lives there):

```rust
/// Non-destructive mana-affordability predicate. Returns true iff
/// `player_id` could pay `cost` right now by consuming floating
/// pool mana (respecting spend restrictions for `spell_kind`) then
/// auto-tapping untapped lands they control. Reads ZERO mutation;
/// snapshots nothing because it never mutates. Mirrors Python
/// `mtg_bot.actions.can_pay_cost` (`src/mtg_bot/actions.py:336-403`)
/// — the SoT — algorithm-for-algorithm.
pub(crate) fn can_pay_cost(
    state: &crate::state::GameState,
    player_id: usize,
    cost: &crate::cards::ManaCost,
    spell_kind: &SpellKind,   // see §2.4
) -> bool
```

`convoke` / `sac_for_mana` are Python parameters that widen coverage
(upper-bound, "only ever makes a spell cheaper"). **Verify-first scope
decision:** the EoE pool's bridge-admitted cards have no convoke and
the sac-for-mana path is the Treasure idiom — neither is on any of the
5 live Rust CastSpell axes' admitted cards. The predicate is specced
**without** convoke/sac-for-mana for the initial slice (matching the
live admitted surface) with a `// PARITY-FORWARD` note that adding
them is a pure widening (never narrows the emitted set) so it can land
later without re-pinning. This is the same surgical-scope discipline
WARP_COST_PHASE2 §1 applies.

### 2.2 The algorithm — shadow Python `can_pay_cost` exactly (`actions.py:359-403`)

new-code-is-right (`feedback_parity_new_code_is_right`): write the
Rust predicate to match the Python SoT; any parity failure means a
Rust bug to fix, not a quirk to mirror. The exact ported algorithm:

1. **Resolve the usable pool.** Python: `usable_pool = [c for c in
   p.mana_pool if _coin_satisfies_context(c, spell_kind)]`
   (`actions.py:364-367`). Rust's `ManaPool` is a **count struct**
   (`white/blue/black/red/green/colorless` u-counts), NOT a list of
   restriction-tagged coins. The Rust mana model has no per-coin spend
   restriction today (verified: `auto_tap_headroom_pool` and
   `pool_can_cover` operate on the bare count struct). **Scope
   decision (evidence-based):** none of the 5 live Rust CastSpell
   axes' admitted cards exercise restricted-coin contexts (those are
   Treasure/Eldrazi/artifact-spend idioms not on the bridge-admitted
   cast surface). So `spell_kind` is **carried in the signature for
   forward-composition but the initial predicate treats the whole
   count pool as usable** (equivalent to Python's behavior when no
   coin carries a restriction — the dominant real case). Document this
   as a deliberate, parity-safe simplification in
   `SEARCH_LIMITATIONS.md` at landing (it is a *narrowing of an
   already-permissive widening direction* — it can only make the
   predicate emit a strict superset of Python in the restricted-coin
   corner, i.e. it preserves the `Rust ⊇ Python` direction that the
   single-script-replay contract needs; §4 proves this is
   parity-neutral pre-flip). The restricted-coin port is a tracked
   follow-up bundled with the alt-cost slice.

2. **Pay colored requirements first — pool, then lands**
   (`actions.py:371-392`). For each of the 5 colors `(color, need)`
   where `need = cost.<color>`:
   - Consume up to `need` from `usable_pool.<color>` first.
   - For the residual, count untapped lands the player controls that
     can produce `color` and aren't already reserved. Python:
     `effective_land_produces(state, l)` (`actions.py:386`) — the
     **effective** producible-color set (UEOT/static-aware). Rust must
     read the analog: a land's producible colors. The live Rust
     auto-tap composer reads `printing.mana_produced` symbols
     (`state_ops_legal.rs:568-588`); the predicate must use the SAME
     source so emission-side affordability is consistent with the
     already-shipped ActivateAbility headroom (no second, divergent
     land-color model). If `available_matching_lands < need` → return
     `false`.
   - Reserve consumed pool slots + land ids so generic can't double-spend.
3. **Pay generic with remaining pool (any color) + remaining lands**
   (`actions.py:400-403`):
   `remaining_pool + remaining_lands >= cost.generic + len(cost.hybrid)`.
   Rust has no `hybrid` field → the term is `cost.generic` (the
   `len(cost.hybrid)` term is 0 for every live axis; §2.5 forward-notes
   the extension). Colorless pool mana counts toward generic (mirror
   `pool_can_cover:528` which already adds `pool.colorless`).
4. Return `true`.

**Cost shapes the predicate must handle** (live surface, evidence-bound):

- **generic + colored** (the only live shape on the 5 axes): handled
  by steps 2–3 above.
- **cost reduction / increase**: the cost passed in is ALREADY the
  effective cost (Python applies `apply_cost_reductions` before
  `_can_cast`; §3 specifies Rust apply the same reduction before
  calling the predicate, so the predicate itself sees a reduced
  `ManaCost`). The predicate does NOT re-apply reductions — single
  responsibility, matching Python where `can_pay_cost` receives an
  already-`_effective_cost`-reduced `ManaCost`.
- **floating mana + untapped sources + known mana abilities**: "can
  pay" = current floating pool PLUS the auto-tap headroom from
  untapped, non-summoning-sick mana sources the player controls
  (lands + `mana_produced` creatures) — exactly the
  `auto_tap_headroom_pool` semantics already proven for
  ActivateAbility (`state_ops_legal.rs:559-591`, pins I50). The
  predicate **reuses `auto_tap_headroom_pool`** as the "effective
  payable pool" rather than re-deriving land tapping — this is the
  single-source-of-truth that keeps the cast gate and the
  already-shipped ability gate consistent (and is why the predicate
  can be `pool_can_cover(&auto_tap_headroom_pool(state, idx), cost)`
  for the colored+generic shape — see §2.3).

### 2.3 The minimal correct implementation (composes existing primitives)

The live tree ALREADY contains both halves of the predicate:

- `pool_can_cover(pool, cost)` (`state_ops_legal.rs:514-530`) — exact
  colored-then-generic affordability over a count pool, mirroring
  `pay_mana_cost`'s pre-mutation gate. **Already correct** for the
  `generic + 5-colored` shape.
- `auto_tap_headroom_pool(state, idx)` (`:559-591`) — the
  non-destructive "pool + every untapped non-sick mana source"
  hypothetical pool. **Already non-mutating, already pins I50.**

So the non-destructive `can_pay_cost` for the live CastSpell surface
is **functionally** `pool_can_cover(&auto_tap_headroom_pool(state,
idx), effective_cost)`. The new `state_ops_mana::can_pay_cost`
**wraps** these two with the named public signature (§2.1) so:
(a) there is one canonical predicate name the SL note can point at,
(b) the alt-cost / restricted-coin / convoke extensions have one place
to grow, (c) it lives next to `pay_mana_cost` (the destructive sibling
the SL note names), keeping the "permissive in `legal_decisions`,
strict in apply" pair co-located. Both helpers currently live in
`state_ops_legal.rs`; the slice moves them (or re-exports them) into
`state_ops_mana.rs` next to `pay_mana_cost` so the predicate and its
destructive twin are siblings — the SL note's exact fix shape.

> **Per-color land-matching subtlety (verify-first catch).**
> `pool_can_cover` over a *headroom pool* treats every credited land
> as already-produced into a fixed-color slot. But a dual-land's
> `mana_produced = ["W","U"]` credits BOTH slots in
> `auto_tap_headroom_pool` (`:578-587`), which would let one dual land
> pay TWO different colored pips — a real over-credit vs Python's
> `can_pay_cost`, which reserves each land id once
> (`actions.py:387,391-392`). **For the live admitted surface this is
> a non-issue** (the bridge-admitted single-color-basic harness idiom
> — see `2026-05-17-cross-feature-interaction-probes` worklog: dual
> producers are normalised to single-color basics precisely because
> they create this ambiguity). The spec records it as a **known
> bounded over-credit** to be closed by porting Python's
> reserve-land-id-once loop (step 2 of §2.2) when a dual-producer card
> joins the live cast surface; until then `auto_tap_headroom_pool`'s
> already-shipped behavior is the parity-consistent choice (the
> ActivateAbility gate has the identical property today and is
> byte-equal-pinned). Documented as a precise bounded gap, NOT
> over-engineered away. This is the WARP_COST_PHASE2 §1 "scope to the
> live surface, forward-note the rest" discipline.

### 2.4 `SpellKind` (forward-composition stub, not used in slice 1)

### 2.5 Forward note — X / hybrid / Phyrexian (NOT a silent gap)

When the alt-cost slice lands X-pip / hybrid / Phyrexian costs into
the Rust `ManaCost` struct, the predicate extends as:

- **hybrid**: add `len(cost.hybrid)` to the generic term (Python
  `actions.py:402` exact). Pure additive — no re-pin of slice-1
  behavior (live `hybrid` is empty).
- **X**: a `can_pay_cost`-bounded `x_upper_bound` mirroring
  `actions.py:510-526` (linear probe `x = 0, 1, ...` until the next X
  is unaffordable). Emission then offers the X cast iff `x_upper_bound
  >= cost.x_pips_min` (1 for "X≥1" cards; 0 always passes).
- **Phyrexian**: a Phyrexian pip is payable by 2 life OR the color;
  the predicate's colored loop gains an "or `p.life > 2` after
  reserving" branch (CR 117.4). No live axis exercises this.

These are explicitly OUT of slice 1 and recorded here so the alt-cost
slice inherits a designed extension point rather than rediscovering

## 3. The precise `legal_decisions` change + the parity contract

### 3.1 Gate each of the 5 live CastSpell emission sites

For each of the 5 Rust emission sites (§1.2), insert the affordability
gate **immediately before the `actions.push(...)`**, computing the
**effective** cost first (the Python parity requires reductions are
applied BEFORE the payability check — `legal.py:187-188` `_effective_
cost` wraps every `_can_cast` arg):

| Site | Cost to check | New gate (pseudocode) |
|---|---|---|
| `:943` base hand instant | effective `printing.mana_cost` | `if !can_pay_cost(self, idx, &eff(mana_cost), &sk) { continue; }` |
| `:964` warp hand instant | effective `printing.warp_cost` | `if !can_pay_cost(self, idx, &eff(warp_cost), &sk) { /* skip warp push only */ }` |
| `:1063` base hand sorcery | effective `printing.mana_cost` | as `:943` |
| `:1074` warp hand sorcery | effective `printing.warp_cost` | as `:964` |
| `:1098` warp exile-recast | effective normal `printing.mana_cost` | `if !can_pay_cost(self, idx, &eff(mana_cost), &sk) { continue; }` |

`eff(...)` = the Rust analog of `apply_cost_reductions` /
`_effective_cost`. **Verify-first scope:** Rust's `cards.rs` has no
`cost_reductions` / `external_cost_reductions` fields on the live
bridge-admitted surface (the bridge declines cost-reduction cards —
`docs/COST_REDUCTION_PHASE1_DESIGN.md` is "realizable-0"). So `eff(c)
= c` (identity) for the live surface; the slice adds the identity
wrapper as the named seam so the cost-reduction slice (if ever
realized) has one insertion point. Document the identity as a
deliberate live-surface simplification in `SEARCH_LIMITATIONS.md`.

### 3.2 What it must STILL emit (the over-prune guard — parity contract)

The fix MUST NOT make Rust's set narrower than Python's on the 5 live
axes. Specifically it must still emit:

- Every base/warp cast Python's `_can_cast` accepts — i.e. the
  predicate must be **at least as permissive** as Python's
  `can_pay_cost` (auto-tap headroom included; this is why §2.3 reuses
  `auto_tap_headroom_pool`, NOT a pool-only check — a pool-only gate
  would WRONGLY drop a `{4}{G}{G}` cast that Python offers when 6
  untapped Forests are on the battlefield, regressing the negative-
  control test `..._collapses_with_sufficient_mana`).
- The warp variant whenever Python's H/C arm would (i.e. `warp_cost`
  payable). Note Rust still cannot gate on `p.life >
  warp_additional_life_cost` (no such field — Phase-2-deferred). This
  is an **accepted residual sub-divergence**: post-fix, on a warp card
  with a positive life rider at lethal-low life, Python omits the warp
  cast (life gate) but Rust still emits it (no life field). Since the
  only such card is Timeline Culler and it is NOT bridge-admitted
  pre-warp-Phase-2 (`WARP_COST_PHASE2_DESIGN.md` §1), this is
  unreachable on the live admitted surface; it is closed exactly when
  warp Phase 2 lands the `warp_additional_life_cost` field (§6
  dependency edge). Record it in the SL entry's "residual" subsection
  at landing.
- The warp exile-recast at normal cost whenever payable.

### 3.3 Target-satisfiability + additional-cost (the other two Python gates)

Python gates emission on `_can_cast` AND `_targets_are_satisfiable`
AND `_additional_costs_payable`. The live Rust CastSpell axes
(`:943/:1063/:1098`) emit a **bare** `cast_spell` dict — they do NOT
carry chosen targets (targets are resolved downstream). The
target-satisfiability prune (`legal.py:79-114`, CR 601.2c — "0 legal
targets ⇒ can't cast at all") is a **second prune axis** Python
applies that Rust also omits.

**Scope decision (evidence-based, mirrors §1.4):** the bridge-admitted
live cast surface is `_printing_is_bridge_simple_spell` /
`_printing_is_bridge_simple_creature` cards. Bridge-simple creatures
(the dominant axis — e.g. the pin's `Slavering Branchsnapper`) have
`spell_effect is None` so `_targets_are_satisfiable` returns `True`
trivially (`legal.py:93`). Bridge-simple spells with a targeted
`spell_effect` (Focus Fire, Radiant Strike, etc.) CAN have 0 legal
targets. **The mana-aware fix (slice 1) closes the mana axis ONLY**;
target-satisfiability is specced as **slice 2** (a sibling prune,
same gate-the-emission shape, needs a non-destructive Rust
`legal_targets` count analog — a strictly separate predicate). Slice 1
is honest about this: it closes the named SL-note problem (mana
payability — "no non-destructive `can_pay_cost`"); it does NOT claim
to close target-satisfiability. The SL entry update (§3.4) narrows the
divergence to the residual target/additional-cost axes rather than
retiring it outright. **This is a sub-slice split — see §5.**

### 3.5 Risk axes

1. **Mana abilities that change available mana mid-decision.** The
   predicate uses `auto_tap_headroom_pool` (a *hypothetical* fully-
   tapped pool). This is correct for emission (Python's `can_pay_cost`
   does the same auto-tap accounting) BUT the apply path stays strict:
   the player must actually tap lands (via separate
   `ActivateAbility(land, 0)` actions) before the cast resolves. This
   is the already-proven "permissive in `legal_decisions`, strict in
   apply" model (`state_ops_legal.rs:551-556`); the cast gate inherits
   the identical, byte-equal-pinned semantics the ability gate already
   has. No new risk — it is the SAME composer.
2. **Interaction with the existing structural filters.** The new gate
   is inserted AFTER the existing `!is_land` / speed / dedup filters
   and BEFORE the `actions.push`. It cannot reorder emissions (it only
   conditionally skips a push). The shared `seen_castspell` dedup
   HashSet (`:921`,`:1058-1062`) must NOT have the card's name
   inserted when the affordability gate skips it (otherwise a later
   same-named affordable copy would be wrongly deduped away). **Precise
   rule:** insert into `seen_castspell` ONLY on the path that actually
   pushes — move the `seen_castspell.insert(name)` to after the
   affordability check, mirroring Python where `_emit_hand_cast`'s
   `seen_instant.add(key)` (`legal.py:241-244`) only runs when the
   emission actually happens (Python checks `_can_cast` before calling
   `_emit_hand_cast`). This is a load-bearing ordering detail — a pin
   covers it (§5).
3. **Warp variant + base independence.** The warp push (`:964/:1074`)
   is gated on its OWN cost (`warp_cost`), independent of the base
   push's `mana_cost` gate. A card whose base cost is payable but warp
   cost is not (or vice versa) must emit exactly the affordable
   subset — mirroring Python where C/H are independent `_can_cast`
   calls on `warp_cost` vs F's on `mana_cost`. Do not share a single
   affordability boolean across base+warp.
4. **`eff()` identity assumption.** If a cost-reduction card ever
   becomes bridge-admitted, the identity `eff(c)=c` silently
   over-prunes (Python would reduce the cost and find it payable; Rust
   wouldn't). Mitigated by: the bridge declines cost-reduction cards
   today (verified); the identity seam is the single named insertion
   point; a pin asserts the live admitted set has no `cost_reductions`
   carrier (regression tripwire).

## 4. The phased, PARITY-NEUTRAL incremental landing path

> **The load-bearing claim:** a correctly-mana-aware Rust legal set is
> a SUBSET of today's structural set that **still contains every
> Python-sourced replayed action** (because Python only ever sources
> an action it deems mana-legal, and the new predicate matches
> Python). Therefore the change is **parity-neutral under the current
> Python-sourced single-script-replay harness** and can land EARLY,
> validated by the existing pins, with ZERO cross-engine parity
> regression — long before the SoT flip.

**Proof of parity-neutrality (the safe-landing argument):**

Every cross-engine harness replays a **Python-derived** `action_dict`
on both engines via `step_both` (verified: `cross_engine.py:10238-10242`;
`SEARCH_LIMITATIONS.md:5396-5420`; the 3 pins in
`test_cross_engine_legal_set_asymmetry.py`). The harness NEVER reads
`rust_state.legal_decisions()` to choose. So the ONLY way the
`legal_decisions` change could affect a cross-engine trajectory is if
some replayed Python-sourced action is one the post-fix Rust enumerator
no longer emits. Python sources an action only when its own
mana-/target-/cost-aware `legal_actions` emitted it ⇒ Python deemed it
payable. The new predicate is specced to be **at least as permissive
as Python's `can_pay_cost`** on the colored+generic shape (§3.2, via
the same `auto_tap_headroom_pool` Python's auto-tap mirrors). Hence
every Python-sourced replayed cast is still emitted by post-fix Rust ⇒
`step_both` still applies it identically ⇒ **byte-equal trajectory
preserved**. The change only REMOVES Rust-only structural casts that
no agent in the current harness could ever pick. ∎

This is the `feedback_no_fallback_hybrids` / honest-progress shape: no
dev-time fallback, the change is genuinely parity-neutral by the
replay contract, not by a wrapper.
