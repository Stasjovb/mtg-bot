## 1. The 10 cards — exact warp shape, grouped by sub-shape

Resolved from the live `OracleParserCardSource` (the printing the
production-deck loader actually sees) cross-referenced with the raw
Scryfall `oracle_text` across all 4 parser data files
(`edge_of_eternities.json`, `stellar_sights.json`,
`special_guests_eoe.json`, `duskmourn.json` — the parser merges all
four; `source.py:34`). Deck counts are 17lands EoE archetype builds
(of ~130k). All 10 are EoE-draftable creatures/enchantments with real
deck-count signal.

Unlike the non-basic-land case (parser silently dropped riders), the
parser here **faithfully structures** the warp keyword into
`CardPrinting.warp_cost` (a `ManaCost`), plus
`warp_cost_str`, `warp_additional_life_cost`, and
`warp_castable_from_graveyard` (`cards/parser/printing_keywords.py`
`_parse_warp_line` / `_parse_warp_with_life_cost_line` /
`_parse_warp_castable_from_graveyard_line`). There is no "parser

layer. The mistranslation risk is entirely at the *bridge + Rust*
layer (§2). Python models the full warp lifecycle: `legal.py:263-292`
emits a `use_warp=True` cast action; `actions.py:1393-1457`

(plus `warp_additional_life_cost`), sets `card.cast_via_warp`, flips
`state.spell_warped_this_turn`, and the end-step turn-based action
exiles the warp-cast permanent (then it is re-castable from exile at
normal cost on a later turn).

### The hard distinction from the round-39 Ward / round-59 sub-shape-A precedents

Round-59 admitted the 5 pay-life shocklands as a *documented
deliberate simplification* because the dropped rider was bit-equal
under the bench's strategy: the parser dropped the rider on **both**
bridge sides (symmetric drop → still bit-equal), AND `attack_all`
never makes the dropped decision. Round-39 Ward was the same: Ward
only fires when a spell *targets* the warded creature, and
`attack_all` never targets it.

**warp_cost does NOT have that property — it is the cost-reduction
class, not the Ward class.** The drop is **asymmetric**:

- **Python** offers the warp-cast as a legal action and, when chosen,
  pays the (cheaper) warp `ManaCost` and exiles the permanent at end
  of turn. **Rust** never offers it and pays the full printed
  `mana_cost`. There is no symmetric-drop bit-equality: the two
  engines do not even present the same *action set* for a warp card
  in hand, and the post-cast mana-pool / zones / `spell_warped_this_
  turn` state diverges.
- It fires on a path the bench strategy **always** exercises: the
  bench plays creatures to attack with them, so it *will* cast them.
  The very first time a warp card is castable, Python's
  `legal_actions` has an extra `use_warp=True` entry Rust's does not
  → the action-set fingerprint mismatches **before any state even
  changes**. This is precisely the cost-reduction / `dynamic_pt_
  formula` / `BECOMES_TAPPED` class of §2 decline: a field one engine
  models, the bridge cannot carry to the other, on a path the harness
  drives.
- Worse than cost-reduction in one respect: cost-reduction at least
  produces the *same legal action* (cast the spell) and diverges only
  on the cost paid; warp produces a **different legal-action set**
  (Python has the warp variant, Rust does not), so the divergence is
  visible at the `legal_actions` comparison, not just post-cast.

There is no `attack_all`-conditional escape hatch and no symmetric-
drop bit-equality. Admitting any of the 10 by widening the filter
gate (`trajectory.py:3307`) would ship a **guaranteed inter-engine
divergence**, not a documented simplification — identical to the
round-60 cost-reduction verdict.

## 3. Phased implementation plan (this IS a multi-round substrate — but smaller than cost-reduction)

There is **no Python-bridge-only phase-1** for warp_cost (contrast
non-basic-land's sub-shape A). Every phase below requires a Rust
change and a `maturin develop --release` rebuild; the substrate is
genuinely multi-round. **It is, however, materially SMALLER than
cost-reduction**: warp is a *fixed* alternative `ManaCost` plus a
deterministic exile-at-end-step replacement — there is **no
`Condition`-grammar port** (the round-60 cost-reduction plan's §3
single largest piece). The closest existing Rust scaffolding is the
already-present `state.spell_warped_this_turn` field +
`Effect::ConditionalIfVoid` consumer (`SEARCH_LIMITATIONS.md`
round-12-era pin) — the substrate's flag-setter "follows trivially
at the warp-cast site" once the cast path routes warp distinctly.
Each phase must leave the gate green
(`tests/test_parity_smoke.py + test_cross_engine_etb_triggers.py +
test_trajectory_parity.py + test_trajectory.py`).

### Phase 1 (Rust + bridge) — CardDef warp field + Rust warp cast + the end-step exile (pure fixed-cost warp)

**Scope:** sub-shape A's two cards **only** (Red Tiger Mechan,
Bygone Colossus) — the pure fixed-`ManaCost` hand-only warp, the
smallest self-contained slice. Requires:
1. `CardDef` gains a `warp_cost: tuple[...] | None` representation
   (the `(generic, colored)` `ManaCost` shape already used by the
   bridge for `mana_cost_generic` / `mana_cost_colored` — frozen,
   bridge-serializable; reuse that codec).
2. `build_rust_state`'s `printing_dict` emits the `warp_cost` key;
   Rust's `register_printing` parses it into a new `CardPrinting`
   field.
3. Rust's `legal_actions` (`state_ops_legal.rs`) gains the alt-cost
   detector: for a hand card whose printing has `warp_cost`, emit the
   second `CastSpell` dict with `use_warp=True` (the 6-tuple dedup
   key already has the `use_warp` slot — `state_ops_legal.rs:119`).
4. Rust's `Action::CastSpell` arm stops discarding `use_warp`: when
   `use_warp=True`, pay `warp_cost` instead of `mana_cost`, set
   `state.spell_warped_this_turn=true` (the flag-setter
   `SEARCH_LIMITATIONS.md` round-12 pin has been waiting for), mark
   the permanent warp-cast.
5. A Rust end-step turn-based action that exiles each warp-cast
   permanent at the next end step (mirror Python `actions.py`
   end-step exile), and a `use_warp`-from-exile re-cast at *normal*
   cost on a later turn (sub-shape A is hand-only — no graveyard arm
   in this phase).
6. Bidirectional bridge arms in `_card_def_to_python_printing` /
   `build_rust_state` to round-trip `warp_cost`.
7. Widen the filter at `trajectory.py:3307` to admit a printing whose
   ONLY blocking feature is `warp_cost` AND whose warp is the pure
   fixed-cost shape (no `warp_additional_life_cost`, no
   `warp_castable_from_graveyard`, no other gate) — a **positive
   allowlist** predicate `_printing_is_bridge_pure_warp_creature`
   (the §2 guardrail, like round-59's
   `_printing_is_bridge_nonbasic_mana_land`).
- **Pin plan:** Rust regression pins for the new field + the
  `use_warp` legal-action emission + the warp cast cost-pay + the
  end-step exile + the exile re-cast; cross-engine bridge pins that a
  Red Tiger Mechan / Bygone Colossus deck offers the SAME
  `use_warp=True` action and pays the SAME warp cost and exiles on
  the SAME end step on both engines (the divergence this closes);
  negative pins that sub-shapes B/C/D stay filtered (the §2
  guardrail's teeth — Timeline Culler rejected on
  `warp_castable_from_graveyard`; Starfield Vocalist on the static
  gate; Codecracker Hound on Effect-uncovered).
- **Genuine-real-EoE-probe:** a mirror game running a real 17lands
  Red Tiger Mechan archetype through `attack_all`, asserting 0
  divergence through the turn the Mechan is warp-cast AND the
  following end step (the exile is the second path that diverges
  today) AND a later turn's re-cast from exile.
- **Phase-1 EoE-pool delta (only if shipped):** +2 cards / +6,450
  decks. **This is a Rust-agent slice gated on `maturin develop
  --release` — it CANNOT be a docs/Python-only round-61 phase-1 the
